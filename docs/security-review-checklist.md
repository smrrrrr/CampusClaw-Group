# 安全自查与人工评审步骤

适用：本轮课程安全基线及后续对应修复。现行要求仍以AGENTS及八类规范为准；本页提供操作步骤，不另造一套授权规则。

## 按什么顺序做

1. 看README、变更proposal/design/tasks及当前业务规约，明确身份、资源和失败信号。已有教学库不得运行dev_seed。
2. 执行安全入口，保存原始结果与时间。若只是重放接口，用独立探针并指定自己的输出文件；临时身份口令不是线上账号口令。
3. 逐项核对SEC-01至07：前置是否成立、请求体是否合法、成功对照是否通过、拒绝后数据是否真的不变。401/403/404和未处理500不能混为一类。
4. 沿业务路径读路由→服务→模型，重点看授权、并发唯一键、短事务、模型外呼位置、旧结果条件写回和确认消息顺序。按下表七类检查逐项说明证据。
5. 运行完整门禁。安全红项保留，不能用门禁绿代替专项结果；不能删断言或改实现后冒充修复前基线。
6. 另一名同学在本人机器独立复现至少2项，填写reports/review-01.md并给本人证据；没有执行就标待验。
7. 后续修复另起业务规约及评审，先保留红色复现，再改实现，最后记录绿色复跑和风险范围。

## 人工需要回答的七类问题

| 类别 | 要查什么 | 通过/失败信号 | 证据位置 |
| --- | --- | --- | --- |
| 接口 | 当前身份从哪里取；合法/非法请求分别怎样响应 | 合法成功；匿名401；越权按主规约拒绝且不泄漏；500不是授权成功 | security-evidence/api-probe.json及对应check脚本 |
| 业务 | 状态是否允许操作，教师人工评分是否被旧AI结果覆盖 | 有效状态完成；旧结果跳过，不覆盖教师分 | async-offline的C2 |
| 数据库 | 唯一键、整批回滚和迁移是否保留旧数据 | 同版本一条任务；中途失败无半批；重复迁移不变 | async-offline的B3/C1/F1 |
| 公共函数 | 是否重用既有权限、评分、错误处理；是否出现分层反向依赖 | layering通过且关键调用符合规约；未量化重复不写“全仓无重复” | full-check及逐文件评审表 |
| 异常 | 外部失败是否可观测、恢复是否可靠、错误有无内部信息 | 明确失败且可恢复；异常吞掉/缺审计列风险 | risk-transaction、逐文件评审表 |
| 安全/隐私 | 跨班、错误角色、配置修改、密钥、依赖、日志字段 | 无越权数据/写入；密钥0命中且范围完整；漏洞有处置证据 | security-precheck、security-baseline |
| 性能 | 是否同步等待模型、是否逐行查询、数据规模是否已测 | 有明确测量范围；不能把假模型20请求推断成生产容量 | async-offline的timing、reports/bench.md |

检查结果分“可用”“待修改”“风险/无效”；每个结论写出具体触发条件、当前保障机制、失效条件和后续方案。未检查的文件标为未覆盖，不按其他文件的结果代填。
