# 08 评审与完成定义规范

**什么时候读：** 每条变更都适用，提交、合并、归档前重点复核。由AGENTS与review-change引用。

**这份规范要保证：** “完成”有可查证据，AI自检、自动门禁和另一人的评审不混为一谈。

## 1. 一条变更怎样算完成

以下五项同时满足才算完成：

| 项目 | 必须有的证据 |
| --- | --- |
| 场景覆盖 | 每个Scenario有对应检查，含失败、越权与边界 |
| 门禁通过 | 完整make check全部PASS |
| AI改动已评测 | 改提示词时有前后评测/抽查；未改则说明不适用 |
| 文档同步 | 按影响范围同步README、主规约、领域规范及模型注释 |
| 验证可追溯 | 变更validation或docs下可按变更名找到记录 |

不能用“模型说完成了”或“其他测试全绿”代替缺失的一项。只整理文档时说明skip_specs及适用检查，不编造业务接口。

## 2. 控制变更与提交规模

一次实现按tasks中的一组推进，一次提交只含一组任务；超出时拆变更或提交。不要把历史遗留和本次改动混成一个“全完成”。

## 3. 谁检查什么

| 角色 | 检查责任 | 不能代替什么 |
| --- | --- | --- |
| 实施者 | 按Scenario实现、自检、留证 | 不能代签另一人 |
| Harness/review-change | 分层、命名、错误、日志、重复代码、检查覆盖 | 不能只凭自述证明功能 |
| make check | 规约格式、分层、密钥、类型和现有回归 | 不能证明未覆盖条款通过 |
| 另一名组员 | 场景正确性、权限、迁移/备份、提示词评测 | 自动报告不等于人工评审 |

评审记录写 `条款/Scenario → 检查名 → 本次结果 → 证据`，没有对应检查就写未覆盖。

## 4. 责任人与时限

每条变更指定一名评审人，收到请求后一个工作日内响应。超期由提出者按组内流程升级，不自行合入main；代理未经授权不发送消息。

## 5. 门禁必须跑，失败必须阻断

合并前在本地执行完整make check，并把本次结果摘要放进评审材料。Windows对应 `backend/.venv/Scripts/python.exe scripts/check.py`。

不能为了变绿而删断言、放宽检查或跳过子项。发现断言可能有错，先按规约说明原因，再调整，保留复现与复跑证据。

## 6. 例外必须书面记录

例外写在对应领域规范，不只在聊天里同意。至少记录：

| 字段 | 要回答的问题 |
| --- | --- |
| 条款与范围 | 哪个对象、文件或接口暂不符合？ |
| 理由 | 为什么当前必须保留？ |
| 责任人 | 谁负责跟进和复查？ |
| 失效条件 | 发生什么就必须整改？ |
| 复查时间 | 哪天或哪个明确评审节点再次核对？ |
| 检查证据 | 怎样知道例外没有扩大？ |

信息缺失就标为未完善，不能借旧例外扩大范围。例外不是允许放宽门禁的通行证。

## 7. 验证记录、提交与归档

变更放 `openspec/changes/YYYY-MM-DD-短横小写英文名/`，按授权在验收后归档。未经明确指示不执行apply/archive、不改任务勾选、不打标签或推送。

提交首行写清改了什么，末尾保留可查的三行，例如：

```text
Change: 2026-10-28-engineering-baseline
Verify: make check
Evidence: docs/lesson-07/verification.md
```

不要只写update/fix。记录时间、环境、提交/工作区状态、命令、数量与退出码；历史记录不改日期冒充本次运行。

## 8. 哪些文件修改后需要人工复核

AGENTS、CLAUDE、.claude、.trae、docs/standards、openspec、scripts、Makefile、Compose和deploy。

说明改了什么、为什么、如何验证。Harness不能自行放宽这些文件里的检查要求。发现流程没走就补流程，判据不清就按变更澄清，不能选择性忽略。

## 9. 课程证据与待验项

课程四维证据在 [第7课目录](../lesson-07/README.md)：A看入口与加载，B看八类覆盖，C看可重放判据，D看组织与自洽。不自行打满分代替教师评分。

教师仓库权限、主干保护、骨架标签、无历史会话、另一成员新机器启动，要分别留真实证据。模板、本机自检、文件存在或模型自述均不能代替。

执行步骤见 [新会话与交叉评审](../lesson-07/review-protocol.md)。新增保证项在 [待讨论清单](待讨论的验收约束.md)，讨论稿尚未自动成为现行门禁。

## 违反时

完成定义任一项缺证据，就不能宣称完成或自行合并。流程缺失先补流程，判据不清按变更澄清；未经授权不归档、打标签、推送或发送消息。
