# 01 产品设计规范

**什么时候读：** 改页面、组件、表单、导航或界面文案时。适用 `frontend/app/**`、`frontend/components/**`。

**这份规范要保证：** 用户知道自己在哪个班级、能做什么，以及操作有没有成功。由 AGENTS 索引；涉及页面的 `add-endpoint` 也要读取。

先记住三件事：页面有四态；切班不能混数据；模型和资料正文统一用已有渲染组件。

## 1. 用户与场景：每个功能落到一个页面

| 谁使用 | 做什么 | 页面 |
| --- | --- | --- |
| 教师 | 导入组内资料、核对学生版、分班发布 | `/teacher/library`、`/teacher/upload` |
| 教师 | 生成、编辑和定稿教案与讲义 | `/teacher/lesson-prep` |
| 教师 | 命题、复核、组卷、发布为作业 | `/teacher/quiz` |
| 教师 | 手工布置、查看提交、初批和改分 | `/teacher?workspace=teaching&view=tools` |
| 教师 | 班级管理、助手/技能/MCP配置、班主任审计 | `/teacher` |
| 学生 | 向学科助手提问、查看出处及会话 | `/student` |
| 学生 | 交作业、错题、学情 | `/student?view=assignments`、`?view=mistakes`、`?view=analytics` |
| 师生 | 浏览本班已发布资料 | `/materials` |
| 全部 | 登录、首次改密、无权限提示 | `/login`、`/change-password`、`/403` |

新增页面先更新这张表。**检查：** 表中的路由都有对应 `page.tsx`，新增功能的 Scenario 能对应到页面。

## 2. 术语：同一个概念只用一个名字

| 界面用词 | 对应含义 | 不要混叫 |
| --- | --- | --- |
| 资料 | material（班级资料） | 不混叫文档；“文件”只指附件本身 |
| 教研组资料 | research_material | 不混叫组内资料、公共资料 |
| 教案 | lesson_plan | 课件、备课稿 |
| 讲义 | handout | 学案、练习纸 |
| 学生版 | student copy / student draft | 学生稿只用于代码与规约 |
| 出处 | citation；学生回答用 `[n]` | 引用来源、参考链接 |
| 题库 / 试卷 | question bank / paper | 题集、卷子 |
| 学科助手 | agent / assistant | 机器人、AI老师 |
| 会话 | conversation | 对话 |

**检查：** 同一屏不要出现两个词表示同一概念。接口字段仍以业务规约为准。

## 3. 页面四态：不能把失败显示成“没有数据”

| 状态 | 页面必须给出的信息 |
| --- | --- |
| 加载中 | `加载中…`，避免重复提交 |
| 正常 | 当前范围、数据及允许的操作 |
| 错误 | `加载失败：<可理解原因>`，并提供重试或下一步 |
| 空状态 | `暂无<对象>`，说明下一步能做什么 |

助手还有一种情况：**检索无命中**。明确说明“未在本班资料中找到依据”，不挂不存在的出处。

**检查：** 用正常数据、空数据、断网/模拟失败分别打开页面。切班时清空旧列表与预览；迟到的旧班回包不能覆盖新班页面。

## 4. 表单与身份：什么时候校验

- 上传文件：选择时检查类型和大小；提交时服务端再次校验。当前通用文件大小上限为50 MB，以接口配置为准。
- 修改密码：提交时逐项提示不满足的密码规则。
- 提问：非空才发送；流式回答结束前禁用输入和重复发送。
- 所有表单控件都有关联标签，不能只靠占位文字。
- 页面先恢复本标签页会话，再由 AuthGate 检查角色；未恢复或角色不符时不挂载业务内容。
- 教师入口只向教师显示，后端仍独立鉴权。共享角色 Cookie 不得误拒合法切班；任课班级与带班班级保持独立。

## 5. 视觉与渲染：复用现有组件

- 颜色使用 `globals.css` 的令牌：brand系列、canvas、surface、ink系列、line系列、success。新语义色先加令牌。
- 间距使用4/8/12/16/24/32 px；正文14–15 px、小标题16 px、页标题22 px。
- 复用 `app-layout`、`markdown-answer`、`material-preview`、`class-selector` 等组件。
- 模型输出与资料正文统一用 MarkdownAnswer（Markdown + KaTeX），禁止 `dangerouslySetInnerHTML`。

**检查：** 新增硬编码颜色只能位于令牌定义；核对公式、选项、填空和认证配图，不只检查原始字符串。

## 6. 键盘和屏幕尺寸

键盘应能走完“登录→助手→提问→出处”。窄屏单列，宽屏侧栏。

**检查目标：** 分别在390 px和1280 px视口操作，记录溢出、不可达按钮和缺标签。没有测过，不能写“响应式已通过”。

## 7. 状态流转：只允许当前状态能做的操作

| 对象 | 主要流转 | 必须保留的边界 |
| --- | --- | --- |
| 候选题 | pending → approved / rejected | 待复核可改；已入库不原地修改，可复制；archived是独立下架标记 |
| 试卷 | draft → final | 草稿可调题序/分值；定稿只读；修改须复制 |
| 作业 | draft → published → closed | 手工先建草稿，命题发布直接published；逾期/关闭提交为400 |
| 提交 | pending → ai_graded → teacher_graded | AI给建议，教师终评；旧AI结果不能覆盖重交或终评 |

作业目前是**整份文字提交、整份百分制总评**。原卷分值不是逐题成绩。已存在的重交后成绩/错题清理策略仍按现有业务合同，不在文档整理时暗改。

学生作业历史保留本人最新提交、时间、教师终评与评语；关闭后只读，不能因关闭而丢失入口。教师进度使用execution_count标注“批改尝试”，attempts只作为消息累计审计，不能混用。

初批受理回执必须放在被点击的作业卡片内，明确新建/复用/跳过和任务编号；失败同处提示，不能只在页面顶部显示细小灰字。查看提交和任务轮询取回提交后，同步当前卡片提交人数；旧班级回包不能更新新范围。检查入口为check_grading_feedback与实际浏览器E3/E4记录。

## 8. 导入与导出：成功必须是完整成功

导入顺序：类型/大小→业务行与归属→整批提交。失败给出原因；CSV行错误有行号时显示行号，日志不记整行原文或手机号。

上限从接口配置、Pydantic或主规约取。尚未定义的CSV行数上限记为缺口，不编造已实现的限制。

导出按角色获取学生版或教师版。学生版不含答案、解析、教师出处；配图失败要提示，不当作完整导出。浏览器打印/另存PDF与后端格式转换分开说明。

## 9. 怎么验，怎么记录

| 检查对象 | 现有入口 |
| --- | --- |
| 题目状态、公式和学生卷 | `apitest/check_question_bank.py` |
| 命题作业、配图、重交与评分 | `apitest/check_quiz_homework.py` |
| 资料/学生稿导入导出及隔离 | `apitest/check_research_materials.py`、`check_lesson_prep.py` |
| 角色页面与切班 | `apitest/check_route_guard.cjs` + 浏览器验收 |

浏览器记录写清：路由及参数、角色、班级、前置状态、操作、期望、实际、截图。自动检查不代替全部页面的四态、标签和窄屏检查。

## 违反时

发现不符合时，先判断是页面清单漏写还是实现偏离；按业务变更流程处理，不能只改说明使结果看起来合格。
