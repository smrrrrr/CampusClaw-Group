# 02 后端开发规范

**什么时候读：** 改 `backend/**/*.py` 或任何接口契约时。由 AGENTS 与 `add-endpoint` 引用。

**这份规范要保证：** 依赖方向清楚、接口结果明确、数据写入完整，失败时不会留下半成品。

先记住：业务不反向依赖路由；外部调用不占写事务；失败返回中文说明，不泄露内部信息。

## 1. 分层与依赖方向

| 层 | 当前模块 |
| --- | --- |
| 接口层 | `main.py`、`routers/`、`deps.py`、`schemas.py`、`logging_setup.py`、`dev_seed.py` |
| 业务层 | `*_service.py`、`services.py`、`mcp_orchestrator.py`、`model_json.py`、`knowledge_tags.py`、`security.py` |
| 适配层 | `llm_service.py`、`embedding_service.py`、`mcp_client.py`、`mcp_crypto.py` |
| 数据层 | `models.py`、`database.py` |
| 配置 | `config.py`、`version.py` |

作业异步初批新增：`grading_worker.py`为进程入口，`grading_service.py`为业务层，`grading_queue.py`为消息代理适配层。HTTP初批只写持久任务；独立投递器发送、消费者调用既有评分函数，结果提交后才确认消息。数据库任务状态不是客户端身份依据。

只允许向下依赖，同层互引允许。业务层不得导入 routers/deps/main；适配层、数据层不得导入业务层。新增模块先登记到 `scripts/check_layering.py`。

**检查：** 分层脚本退出码为0；新模块未登记或出现反向依赖时必须失败。

## 2. 接口命名与版本

- 角色前缀：`/api/teacher/...`、`/api/student/...`；共用资料为 `/api/materials/...`；另有 auth/mcp/health。
- 资源名用小写复数，多词用短横线，例如 `lesson-plans`、`tool-calls`。
- GET读取，POST创建，PUT整体替换，PATCH局部更新，DELETE删除。
- 动作使用 `POST /资源/{id}/动作`，例如试卷finalize/publish。
- 新路由用 `APIRouter(prefix=..., tags=[...])`，在main注册；写summary及可能的错误响应。

当前未使用 `/api/v1`。需要与旧版并存的不兼容接口应另起 `/api/v2`，不能突然改掉现有路径。历史例外见末尾。

## 3. 请求、响应与错误

请求/响应用Pydantic模型声明，路由写 `response_model=`。成功返回资源对象或列表；`{items,total}` 等列表结构与同模块已有契约保持一致。

失败统一为 `HTTPException(status_code, detail="中文说明")`，响应体为 `{"detail":...}`。每个响应带 `X-Request-ID`。

| 状态码 | 表示什么 |
| --- | --- |
| 400 / 422 | 参数、类型、格式或枚举非法 |
| 401 | 未登录、令牌无效/过期 |
| 403 | 角色、学科、班级不符，或尚未首次改密 |
| 404 | 资源不存在；私有资源的隐藏边界以主规约为准 |
| 409 | 状态不允许、版本冲突、发布冲突 |
| 503 | 数据库、模型等依赖不可用 |
| 500 | 未处理故障；只返回通用中文说明 |

**禁止：** 在detail或日志中回传SQL、物理路径、异常原文、堆栈或密钥。现有系统不用独立分区错误码，不能按一个不存在的code字段验收。

## 4. 校验放在哪里

| 校验 | 位置 | 预期 |
| --- | --- | --- |
| 结构、类型、长度、枚举 | 接口层Pydantic/路由参数 | 非法输入400/422 |
| 状态、版本等业务规则 | 业务服务 | 不允许的操作409 |
| 角色、班级、学科与归属 | deps或业务服务 | 按主规约拒绝，不依赖前端隐藏 |

非法筛选不能被忽略后返回全量。读取目标ID时，先取实际资源，再核对归属。

## 5. 数据访问与事务

1. 查询使用SQLAlchemy ORM或参数绑定的text，不拼接外部输入。
2. 一个请求使用一个Session；跨表写入在同一事务提交，失败整批回滚。
3. 模型/MCP外呼前取出所需数据，结束读取事务；外呼结束后重新检查状态，再开事务写回。
4. 排序加唯一兜底键，例如时间相同后按ID排序。

**检查：** 注入第二项写入故障，不能留下部分业务行或新文件；外呼期间另一会话重交/终评，旧结果不能覆盖新状态。

## 6. 幂等：重试不能变成重复业务

每个新增写接口都要在规约中说明是否幂等。发布唯一性必须有数据库约束，不能只靠“先查有没有”或禁用按钮。

唯一键以业务合同为准。命题作业使用“源试卷+班级+快照指纹”；相同有效截止时间复用原作业，改变截止时间或已关闭时返回409。同一对象面向同一班级的一次发布，不得重复制造提交和成绩。

## 7. 配置外置

- 地址、密钥、开关、阈值从 `config.Settings` 读取，不散落在代码里。
- JWT_SECRET_KEY必填，无默认值，至少32字符；缺失/过短启动失败。
- 非敏感设置可有明确的开发默认值，如数据库路径、上传目录、模型名/地址、枚举、超时和检索参数；以Settings定义为准，新增值说明环境、理由和边界。
- 可选模型/MCP的空值只表示未配置，不是可用的默认密钥。
- 提示词、错误文案、知识点词表等随版本变化的内容属于代码，不放.env。

## 8. 日志

使用 `logging.getLogger(__name__)`，不用print。业务日志自动为单行JSON并带request_id，额外字段用extra传入。

令牌、口令、密钥、Cookie、学生提问原文和资料正文不得进入日志。具体字段及查看方法见 [05部署运维规范](05-部署运维规范.md) 第4节。

## 9. 怎么验，以及当前边界

| 要求 | 现有检查入口/通过信号 |
| --- | --- |
| 分层 | `scripts/check_layering.py`，0违规 |
| 错误、配置、日志 | `apitest/check_baseline.py`，错误码及公开字段符合合同 |
| 原子发布、幂等、评分竞态 | `apitest/check_quiz_homework.py`、`check_question_bank.py`，编号/行数/文件/成绩均符合预期 |
| 非法筛选 | 对所改接口补合法与非法值检查；不能只验证有items字段 |

**现状：** 模型Key为空时应用仍可启动，health显示model=not_configured，生成能力受限；MCP未配置不能显示已连接。这是既有降级策略。若要所有外部密钥缺失都阻止启动，须另起行为变更，不能只改文字。

### 既有书面例外

| 例外 | 原因及边界 | 何时结束 |
| --- | --- | --- |
| services.py、agent_service.py抛HTTPException | 历史实现，只许减少不许新增 | 下次修改对应文件时迁到业务异常，由路由转换 |
| upload-material旧动词路径；materials/research_materials路由未用prefix | 兼容现有调用，新接口不能照抄 | 另行接口迁移时处理 |
| 无/api/v1 | 兼容现有前端与主规约 | 首个需并存的不兼容接口启用/api/v2 |
| 未用统一code/message/data/request_id响应包 | 沿用detail及请求头；取舍见工程基线design | 按该变更记录的失效条件处理 |

## 违反时

发现偏差先区分实现缺陷与规范缺失。按变更修正，不放宽断言来让门禁变绿。
