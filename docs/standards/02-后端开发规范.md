# 02 后端开发规范 · CampusClaw

适用：`backend/**/*.py` 与对外接口契约。
被谁读到：`AGENTS.md` 规范索引（改 `backend/` 时必读）；技能 `add-endpoint`。

## 1. 分层与依赖方向

```
接口层   main.py · routers/* · deps.py · schemas.py · logging_setup.py · dev_seed.py
业务层   *_service.py · services.py · mcp_orchestrator.py · model_json.py · knowledge_tags.py · security.py
适配层   llm_service.py · embedding_service.py · mcp_client.py · mcp_crypto.py   （模型、向量、MCP 等外部能力）
数据层   models.py · database.py
配置     config.py · version.py
```

依赖只能自上而下，同层互引允许。业务层不得 import `routers`、`deps`、`main`；适配层与数据层不得 import 业务层。新增模块先在 `scripts/check_layering.py` 的 `LAYERS` 登记层级。
判据：`python scripts/check_layering.py` 通过；它在 `make check` 中自动执行。

**例外（书面）**：`services.py` 与 `agent_service.py` 在业务层抛出 `fastapi.HTTPException`。理由：历史代码，改动需同时调整多个路由的错误处理。只许减少不许新增；失效条件：下次修改这两个文件的变更中改为抛业务异常、由路由层转换。

## 2. 接口命名

- 路径按调用方角色分前缀：教师端 `/api/teacher/...`（如 `/api/teacher/lesson-plans`、`/api/teacher/quiz`、`/api/teacher/skills`、`/api/teacher/research-materials`），学生端 `/api/student/...`，两端共用 `/api/materials/...`，另有 `/api/auth`、`/api/mcp`、`/api/health`。
- 资源用小写复数，多词用连字符：`lesson-plans`、`research-materials`、`tool-calls`。
- 方法语义：列表与详情 GET，创建 POST，整体替换 PUT，局部更新 PATCH，删除 DELETE。动作型接口用 `POST /资源/{id}/动作`（如 `/lesson-plans/{id}/finalize`、`/quiz/papers/{id}/publish`、`/mcp/servers/{id}/connect`），不写动词开头的路径。
- 新路由文件用 `APIRouter(prefix=..., tags=[...])`，在 `main.py` 中注册；路由函数写 `summary` 与可能的错误响应（参考 `routers/quiz.py`、`routers/mcp.py`）。

**例外（书面）**：`POST /api/teacher/upload-material` 是动词式旧路径，`routers/materials.py`、`routers/research_materials.py` 未用 `prefix`。保持兼容，新接口不得照抄。

**例外（书面）**：路径没有 `/api/v1` 版本前缀。理由：前端 `lib/api.ts` 与 21 份主规约都按现有路径编写。失效条件：出现第一个需要与旧版并存的不兼容接口时，新接口起用 `/api/v2/`。

## 3. 请求与响应结构

- 请求与响应体用 `schemas.py`（或路由文件内）的 Pydantic 模型声明，路由写 `response_model=`。
- 成功：直接返回资源对象或列表；列表接口返回 `{items, total}` 形式时与同模块已有接口保持一致。
- 失败：统一 `HTTPException(status_code, detail="面向用户的中文说明")`，响应体 `{"detail": ...}`；每个响应都带 `X-Request-ID` 头（`logging_setup.RequestContextMiddleware`）。

| HTTP | 用在 | 示例 detail |
| --- | --- | --- |
| 400 / 422 | 参数非法、格式不支持 | “不支持的文件类型” |
| 401 | 未登录、令牌无效或过期 | “认证失效，请重新登录” |
| 403 | 角色、学科、班级不符；未改初始密码 | “仅教师可执行该操作” |
| 404 | 资源不存在 | “资料不存在” |
| 409 | 业务规则冲突（状态不允许、并发修改） | “任课老师已调整，请新建本学科对话” |
| 503 | 依赖不可达（数据库、模型未配置或失败） | “数据库暂不可用，请稍后重试” |

`detail` 不得包含 SQL、文件路径、异常原文或堆栈；未处理异常由中间件返回通用 500。
**例外（书面）**：未采用 `{code, message, data, request_id}` 统一结构与分区错误码。理由与失效条件见变更 `2026-10-28-engineering-baseline` 的 design.md 取舍 1。

## 4. 校验位置

结构、类型、长度、枚举的校验放在接口层（Pydantic 模型或路由参数）；业务层只做业务规则校验（如“已定稿的教案不能再重写”），返回 409。权限判定放在 `deps.py` 依赖或业务层的归属检查里，不放前端。
判据：把某个必填校验挪进业务层，`make check` 中对应的 422 用例会变红。

## 5. 数据访问与事务

- 只用 SQLAlchemy ORM / `text()` 参数绑定，不拼接 SQL 字符串。
- 一个请求一个 `Session`（`Depends(get_db)`）；跨多表的写在同一事务内提交，失败整体回滚（如学生导入整批回滚）。
- 事务内不得夹带模型调用、MCP 调用等外部请求：先取数据、提交或关闭事务，再调用外部，最后开新事务写结果。
- 排序必须有唯一兜底键（如 `order_by(created_at.desc(), id.desc())`）。
- 非法筛选值返回 400/422，不得静默忽略筛选而返回全量。

## 6. 幂等

新增写接口在规约中写明是否幂等。发布类接口（资料、教案、试卷发布到班级）按“同一对象 + 同一班级只有一条发布记录”实现，唯一性落在数据库约束上，不靠“先查有没有”。

## 7. 配置外置

地址、密钥、开关、阈值只从 `config.Settings` 读取（环境变量 / `.env`）。密钥类配置不给默认值，缺失即启动失败（`JWT_SECRET_KEY` 至少 32 字符）。
允许带开发默认值的只有：`DATABASE_URL`、`UPLOAD_DIR`、`FRONTEND_ORIGINS`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 与检索 / 超时类数值参数（Compose 会显式覆盖部署值）。新增此类默认值要写进本条。
随版本变化的东西（提示词、错误文案、知识点词表 `knowledge_tags.TOPICS`）属于代码，不进 `.env`。

## 8. 日志

用 `logging.getLogger(__name__)`，不用 `print`。日志自动输出为单行 JSON 并带 `request_id`；额外字段用 `extra={...}` 传。不得记录：令牌、口令、密钥、Cookie、学生提问原文、资料正文。字段规范见 05-部署运维规范 §4。

## 违反时

判断是一次性的实现偏差还是规范缺失：前者改代码；后者改本文件并在变更说明里写明改了哪条、为什么。
