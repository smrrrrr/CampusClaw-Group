# 03 安全开发规范

**什么时候读：** 全部代码都适用，尤其是登录、权限、附件、上传、出站请求和依赖变更。

**这份规范要保证：** 用户只拿到有权访问的数据，密钥与教师答案不会外泄。三条硬约束常驻AGENTS；此处解释如何检查。

## 1. 默认拒绝：先查资源，再查归属

- 业务接口默认要求登录，使用get_current_user或更严格的教师/学生/学科/班主任依赖。
- 主应用免认证的接口只有login、refresh、health。
- 按ID读取资源时，先查真实行，再核对角色、班级、学科和本人归属。
- 每个读写需求都要有未登录、他人/他班、错误角色检查；涉及学科时还要测他科。

**通过信号：** 一班学生取二班资料必须被拒绝，响应没有对方正文；403记录可在审计中查到。

**书面例外：** 跨班返回403并审计，而非统一404，这是class-data-isolation的合同。403/404有可区分性；如后续改为404，须另起变更并保留审计。私有题目/源试卷的404边界以对应主规约为准。

## 2. 身份只取服务端会话

角色、本人班级、任教班级、学科，从令牌解析后的CurrentUser及数据库取得。不把query/body/header里的同名字段当身份，不接受额外role/is_admin冒充。

需要区分两件事：

| 字段含义 | 怎么处理 |
| --- | --- |
| “我是谁、我属于哪个班” | 只取服务端会话 |
| 契约允许选择的目标class_id | 可以作为目标输入，但必须逐一与服务端权限核对 |

**检查：** 学生附加他班class_id或role=teacher，不能得到更多权限。隐藏前端按钮不算服务端授权。

## 3. 密钥与口令

- 明文密钥只在本机根目录.env，模板只留键名、空密钥及必要说明。
- 代码、提交历史、镜像、前端产物、提示词、日志、响应、问题单和截图不得出现密钥。
- 口令只存bcrypt哈希；MCP令牌用Fernet加密保存且不回传。
- 扫描发现泄漏，处理顺序是轮换、核查影响、记录处置。删文件不能代替轮换。

**检查：** `scripts/secret_scan.py` 随make check执行。它检查本机当前密钥在本地引用历史/工作区中的命中及通用密钥形态；不能据此证明未取得的远端历史或所有已轮换旧密钥都安全。

## 4. 登录、会话与页面守卫

- 初始密码首次登录必须改密；登录错误不区分账号不存在或口令错误，连续失败锁定。
- 安全要求是改密/重置后旧令牌不能继续业务访问。当前已有重置后强制改密拦截的检查；普通改密后的全部旧令牌撤销不能仅凭“查了数据库”宣称已验证。
- Access Token仅在内存和Authorization头中，不放localStorage、URL或日志；Refresh Token仅放HttpOnly Cookie。
- cc_role/cc_has_token是共享辅助提示，不代表当前标签页身份。
- middleware允许页面启动；AuthGate恢复本页会话并检查路径角色，检查通过前不能挂载业务内容。真正的数据授权仍在后端。

**检查：** 合法教师切班不能被另一标签页的角色提示误拒；真实学生进入教师页仍为403，伪造提示不能获得教师内容。

## 5. 外部内容、上传与出站请求

上传正文、技能文件、工具返回和模型输出都是数据，不能成为改变系统规则的指令。

- 模型消息明确数据边界；Markdown/公式使用既有安全渲染，不用dangerouslySetInnerHTML。
- 图片只使用导入原图，核对SHA-256，不加载外链。
- 上传校验类型白名单、枚举和大小；当前通用上限50 MB。落盘名由服务端生成。
- SQL参数绑定，不拼外部输入。
- MCP主机必须与MCP_ALLOWED_HOSTS的host:port精确匹配，不能绕过出站白名单。
- 错误不带SQL、物理路径、堆栈或异常原文。

**检查：** 含脚本的资料不执行脚本；含“忽略规则”文字的资料不改变助手权限；白名单外主机被拒绝。

## 6. 附件读取：不能只凭文件ID放行

先查所属资料/作业，再核对其角色、班级、学科和发布状态。作业图是独立副本，源资料权限不能代替作业权限。

| 输入/身份 | 预期结果 |
| --- | --- |
| 未登录 | 401，无文件字节 |
| 他班、他科或错误角色 | 按主规约403/私有源404，无正文与物理路径；403有审计 |
| 非法图名 | 400，拒绝路径穿越 |
| 不存在的图 | 404 |
| 缺失或指纹不符 | 409，原业务行/文件不被修改 |

图名规范化后，路径仍要限制在允许根目录内。禁止增加凭任意文件ID或路径读取的通用接口。

## 7. 依赖与漏洞

- 新增依赖写入pyproject.toml/package.json及锁文件。许可证限MIT、BSD、Apache-2.0、ISC、PSF；其他需组内评审。
- 新增/升级依赖当次、正式发版前必须审计；长期不发版至少每月复核一次。
- 前端运行 `npm audit --omit=dev`；后端/MCP记录所用扫描器与漏洞库版本。
- high/critical未处理不能正式发布。不受影响的判断必须给攻击前提、证据、责任人和复查日期。

**现状：** 联网漏洞扫描不在make check中。离线通过不代表没有漏洞。

## 8. 怎么验，不符合时怎么办

| 检查 | 现有入口 |
| --- | --- |
| 密钥/禁止跟踪文件 | `scripts/secret_scan.py` |
| 角色与班级、资料隔离 | `apitest/check_lessons_2_5.py` |
| 作业正文与配图隔离 | `apitest/check_quiz_homework.py` |
| 私有源试卷与题库 | `apitest/check_question_bank.py` |
| 工具鉴权与出站主机 | `apitest/check_mcp_tools.py` |
| 页面实际角色 | `apitest/check_route_guard.cjs` + 浏览器 |

## 违反时

发现缺少检测能力时补检查；发现泄漏先轮换，并由发现人通知组长组织处置。未执行的安全检查保留待验，不能写成PASS。
