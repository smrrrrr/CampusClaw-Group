# 07 数据规范 · CampusClaw

适用：`backend/models.py`、`backend/database.py`、`backend/uploads/`、`data/`、组内数据包。
被谁读到：`AGENTS.md` 规范索引（改上述文件或表结构时必读）；技能 `data-change`。

## 1. 命名与类型

- 表名小写复数下划线：`users`、`classes`、`materials`、`material_chunks`、`lesson_plans`、`mcp_servers` 等。
- 时间统一 UTC（`models._utcnow`），字段后缀 `_at`。
- 状态用 Python `enum` 或固定字符串集合，在模型注释里写清取值与流转。
- 归属字段非空：班级资料带 `class_id`，教研组资料与题库带 `subject`，教师私有数据带 `teacher_id`。它们是授权判定唯一可依赖的字段。

## 2. 审计字段

- 新业务表必须有 `created_at`；可修改的表还要有 `updated_at`（`onupdate=_utcnow`）；由人创建的记录带创建人 ID（如 `teacher_id`、`uploader_id`）。
- 版本类数据只增不改：教案版本 `lesson_plan_versions`、发布记录 `*_publications` 新增行，不覆盖旧行。
- 越权与关键操作写 `audit_logs`；MCP 调用写调用记录。

## 3. 迁移纪律

现状：建表靠 `Base.metadata.create_all`，存量库增列靠 `database.run_simple_migrations()` 中的条件化 `ALTER TABLE`。规则：

- 只加不改：新增列先 `PRAGMA table_info` 判断再 `ALTER TABLE ... ADD COLUMN`，可重复执行；不在迁移里删列、改类型、删表（`materials` 骨架表重建是历史例外，已不再触发）。
- 结构变更先加后删：加字段 → 新代码兼容读写 → 发布 → 确认后再另起变更删旧字段。
- 每次迁移在变更 design.md 里写回滚动作（通常是“恢复发布前备份”）。
- 改表结构前必须先备份（技能 `data-change` 第 1 步）。

## 4. 数据字典

字段含义写在 `models.py` 的类文档字符串与字段注释里，对外语义写在对应能力的主规约里，两处是唯一来源。结构变更必须同步二者。

## 5. 敏感分级

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| 公开 | 错误提示、帮助文案 | 可直接返回 |
| 内部 | 班级名、资料标题、教案标题 | 只对本班 / 本学科 / 本人可见 |
| 敏感 | 教师版资料与答案、教研组资料正文、切片内容、题目答案 | 不进日志；学生端只见去答案的学生版 |
| 个人信息 | 学号姓名、手机号、提问与会话记录、登录记录、审计记录 | 不进日志；导出与数据包须脱敏或清空 |
| 机密 | 口令哈希、JWT 密钥、模型 Key、MCP 令牌 | 口令只存 bcrypt 哈希；MCP 令牌 Fernet 加密存储且不回传；密钥只在 `.env` |

组内数据包只能含“内部 / 敏感”级教学数据；个人对话、提问日志、审计、登录记录、MCP 令牌必须清空（2026-10-25 数据包已按此执行）。数据包不上传 GitHub。

## 6. 留存与删除

一条资料存在于这些地方，删除时按清单逐项处理：

| 副本 | 位置 | 删除方式 |
| --- | --- | --- |
| 业务记录 | SQLite `materials`、`material_contents`、`material_assets`、`*_publications` | 教师删除接口事务内删除 |
| 检索切片与向量 | SQLite `material_chunks`（`embedding` BLOB） | 同一事务内删除 |
| 原文件与配图 | `backend/uploads/` | 事务提交后删除物理文件 |
| 浏览器缓存 | 学生本机 `localStorage` 的最近搜索 / 提问 | 只存问题文字，由用户清除 |
| 备份 | `data/current/before-*.db`、组内数据包 | 不自动清理；收到删除请求时人工处理并记录 |

- 学生提问与会话保留一学期（目标）。**现状（书面）**：尚无自动清理任务，学期末由组长手工导出备份后清理，失效条件：实现清理任务的变更归档时。
- 每学期做一次删除演练：建一份资料 → 删除 → 逐项检查上表各处是否清空，记录用时。

## 7. 跨存储一致性

写入顺序：先落文件，再写业务行与切片（同一事务）；失败时删除已落的文件。删除顺序相反：先在事务内删业务行与切片并提交，再删物理文件（`DELETE /api/teacher/materials/{id}` 已按此实现）；文件删除失败只记日志，可重复执行清理。新增涉及文件与数据库的写路径必须遵守同一顺序。
判据：在删除接口中途制造一次文件删除失败，业务行已删除、重试后文件被清理。

## 8. 测试数据

真实数据（`data/current/`）不进测试；离线回归在临时库自建数据。演示账号口令只用于开发演示，不得用于任何正式部署；**已有数据的库不运行 `dev_seed.py`**（会重置学生账号）。

## 违反时

结构变更未同步模型注释与主规约的，先补再合并；删除演练发现未清理的副本，补进 §6 清单。
