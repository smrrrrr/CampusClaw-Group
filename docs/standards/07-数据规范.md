# 07 数据规范

**什么时候读：** 改models/database、表结构、uploads或数据包时。由AGENTS与data-change引用。

**这份规范要保证：** 数据归属明确，迁移不丢旧数据，删除和备份能追踪到所有副本。

先记住：真实库不做测试；结构变更先备份；公开题面与教师答案分开。

## 1. 命名与类型

- 表名用小写复数和下划线，如users/material_chunks。
- 时间统一UTC，时间字段以_at结尾。
- 状态使用enum或固定集合，在模型注释中写清流转。
- 归属字段作为授权依据：班级资料class_id、教研资料/题库subject、私有对象teacher_id；按业务模型保证非空。

## 2. 审计与版本

- 新业务表有created_at；可修改表增加updated_at；人创建的记录带创建人ID。
- 版本/发布记录只增不覆盖，例如lesson_plan_versions和*_publications。
- 越权与关键操作写audit_logs；MCP调用写对应记录。
- 删除题目不顺带删掉用于追溯的审计。

## 3. 迁移纪律

现有建表使用Base.metadata.create_all；旧库加字段通过run_simple_migrations的条件化ALTER。

1. 操作真实结构前备份数据库及匹配文件。
2. 先查列是否存在再ADD COLUMN；迁移可重复执行，不在其中删列、改类型或删表。
3. 新字段先兼容读写，发布确认后另起变更再删旧字段。
4. design写明回滚，通常恢复发布前匹配备份；不要靠删列或dev_seed回滚。

历史materials骨架表重建是已不再触发的例外，不扩展到新迁移。

**检查：** 在临时旧库连续迁移两次，比较旧账号、资料、评分、索引及文件指纹，不能只看建表没报错。

## 4. 数据字典与题面/答案隔离

字段含义写在models.py注释；对外语义写在对应主规约。结构变更同步这两处，不再维护互相矛盾的第三份字段定义。

| 作业数据 | 允许用途 |
| --- | --- |
| source_type | 区分manual与quiz |
| 公开题面stem/format/original_total | 可返回学生 |
| grading_snapshot_json | 私有标准答案、解析和原卷分值，只给服务端与授权教师 |
| source_paper_id/来源版本/指纹 | 溯源及重复发布保护，不靠原试卷维持已发布题面 |
| homework_assets | 独立作业图副本，按作业/班级/教师归属保存SHA-256并鉴权 |

作业和私有评分依据不写资料检索切片。详见quiz-homework-publication主规约。

## 5. 敏感分级

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 公开 | 通用帮助和错误说明 | 可直接展示，不带内部信息 |
| 内部 | 班级名、资料/教案标题 | 按本班、本学科、本人范围读取 |
| 敏感 | 教师原稿、题目答案、解析、切片 | 不进日志，学生仅见学生版 |
| 个人信息 | 姓名学号、手机号、会话、提问、登录/审计记录 | 不进日志，导出与数据包脱敏或清空 |
| 机密 | 口令哈希、JWT/模型/MCP密钥 | 口令只存bcrypt哈希；MCP令牌用Fernet加密且不回传；明文密钥只在.env |

组内教学包只含内部/敏感教学资料；个人会话、提问/登录/审计日志及MCP令牌清空。2026-10-25数据包的处理属于历史记录，不能代替以后每个包的检查。包、数据库和uploads不进Git。

## 6. 留存与删除：逐个副本核对

| 副本 | 实际位置 | 怎么处理和验收 |
| --- | --- | --- |
| 业务正文、版本、发布、评分 | SQLite，具体表见models | 列出关联表及应删/应留行；不能一概cascade删除 |
| 资料切片与向量 | 同一SQLite的material_chunks等，embedding列 | 资料删除后对应切片为0；当前没有独立向量服务 |
| 原文件与配图 | backend/uploads | 提交后清理物理文件；检查路径/指纹/存在性 |
| 作业冻结副本 | 作业记录与uploads | 原资料删除不等于作业副本应删，按作业合同保留 |
| 初批任务私有输入与执行记录 | SQLite grade_tasks，含作答版本与评分依据 | 与作业一同受权保留；未来删除作业时一并列清，不能只删除提交；学生响应和日志均不返回input_json |
| 初批消息与死信 | RabbitMQ持久卷；消息只有任务编号 | 成功后确认普通消息，死信保留供排查；人工重试后历史死信仍可能存在，死信条数不等于当前失败任务数；未来删除须核对普通队列、死信与备份 |
| 浏览器历史及临时资源 | localStorage等 | 按账号/班级/学科隔离；用户清空后不再显示；令牌不持久保存 |
| 备份、私下数据包 | data/backups、历史before库及包 | 不自动随线上删除清除；记录负责人、保留依据、到期与删除结果 |
| 独立对象存储 | 当前未部署 | 不伪造S3删除证据；引入时先补此表 |

学生提问/会话保留一学期是目标；目前无自动清理，由组长学期末先备份再清理。清理任务实现归档后，该临时安排失效。

教师终评及格后，应在改分事务内移除对应的派生错题，不删除提交或成绩；历史残留使用先备份、默认dry-run、按实际终评和归属匹配的repair_resolved_mistakes.py修复，不能无差别清空错题。

关闭作业不删除题面、图、提交、成绩。目前无作业删除接口；将来要清理须另起变更，同时处理私有快照、图、错题与备份。

**检查目标：** 每学期至少做一次独立目录删除演练，记录对象ID、各处应删/应留、实际行数/文件及用时；接口200不代表副本处理完成。

## 7. 文件与数据库的一致性

写入顺序：先文件→同事务业务行/切片→提交。失败清理本次新文件，不能误删既有副本。

删除顺序：先事务删除业务行/切片并提交→再删物理文件。文件清理失败记日志并可重试，不伪称已全部清理。

**检查：** 注入写入失败确认无部分记录/新文件；注入删除文件失败，业务结果与剩余文件可查，补做清理后文件消失。

## 8. 测试与演示数据

离线检查自建临时库，不读真实data/current。**已有数据的库不运行dev_seed**，它会重置账号。演示口令只用于开发演示，不能当正式部署凭证。

## 9. 验证记录与现状边界

使用check_quiz_homework检查旧库重复迁移及冻结副本；资料删除/切片/配图检查见check_research_materials、check_lesson_prep及对应接口用例。

记录备份位置、integrity_check、关键行数、文件指纹、回滚步骤和演练结果。没有运行过就标待验；表结构变更缺模型注释/主规约同步时不能合并，副本清单缺项先补规范。

## 违反时

结构变更缺少模型注释或主规约同步时不能合并；副本清单缺项先补清单。失败时保留库与文件的实际状态，按已记录的备份/清理方案处理，不运行种子脚本或删除旧数据来掩盖问题。
