# 04 测试规范 · CampusClaw

适用：`apitest/**`、`scripts/check*.py`。
被谁读到：`AGENTS.md` 规范索引（改 `apitest/` 或实现任何规约任务时必读）；技能 `add-tests`。

## 1. 层次与位置

| 层次 | 放哪里 | 覆盖什么 | 怎么跑 |
| --- | --- | --- | --- |
| 离线回归（主力） | `apitest/check_<能力>.py` | 用 FastAPI `TestClient` + 临时 SQLite + 假模型，覆盖一条能力的正常 / 失败 / 边界 | `make check` |
| 前端逻辑 | `apitest/check_<模块>.cjs` | 不依赖浏览器的前端纯函数（Markdown 图片、最近记录） | `make check` |
| 在线接口 | `apitest/cases/api/<路径>/<方法>.py` | 对运行中的服务发真实 HTTP 请求，HTTP 与数据库两层断言 | 启动服务后 `python apitest/run_all.py`，不在门禁内 |
| 真实模型探针 | `apitest/probe_*.py` | 需要模型额度的人工抽查 | 手动，结果写进验证记录 |

新能力至少新增或扩展一个 `check_*.py`；门禁自动收集 `apitest/check_*.py` 与 `check_*.cjs`，无需登记。

## 2. 用例来源：说得出在判哪一条规约

每条检查名写清对应的规约场景，格式“`R<编号> <类别>：<场景要点>`”或直接引用场景标题，例如 `R2 失败：学生调用教师接口 → 403 且带请求标识`（见 `apitest/check_baseline.py`）。
说不出在判哪一条场景的检查，通常是顺手写的形状检查，删掉比留着好。

## 3. 三类组织

每条能力按三类归组，缺一类视为覆盖不全：

- **正常路径**：本班学生检索命中并带出处；教师定稿后发布到任教班级。
- **失败路径**：至少覆盖参数非法（422/400）、未登录（401）、无权限（跨班 / 跨学科 / 学生调教师接口，403）、资源不存在（404）、依赖不可达（数据库 503、模型未配置 503、MCP 不可达）。
- **边界**：长度、数量、阈值的两端（如请求标识 7/8/64/65 个字符、`JWT_SECRET_KEY` 31/32 个字符、分页最后一页之后）。用等价类与边界值，不用随机值。

越权用例成对出现：每个读接口一条“他人账号访问”、一条“未登录访问”。

## 4. 断言值，不只断言形状

下面这种写法把被测逻辑改坏仍然是绿的，不允许单独出现：

```python
check('返回成功', response.status_code == 200)
check('有数据', len(response.json()) > 0)
```

要断言值与数据变化：跨班请求后响应里没有对方资料标题；发布后数据库里恰有一条发布记录；失败后数据行数不变；日志里不含令牌原文。
判据：故意改坏被测逻辑（删掉一个归属判断、改错一个状态码），对应检查必须变红。新增检查时至少做一次这样的验证，并写进验证记录。

## 5. 数据隔离

- 离线回归一律在 `tempfile.TemporaryDirectory()` 下建临时库与上传目录（`DATABASE_URL`、`UPLOAD_DIR` 指向临时路径），**不读写 `data/current/` 的真实数据，不运行 `dev_seed.py`**。
- 每个脚本自建所需的班级、教师、学生，不依赖其他脚本的执行顺序。
- 在线接口用例只读演示数据，写入的数据用 `uuid` 命名并在用例末尾清理。

## 6. 外部依赖用替身

模型、MCP 工具服务、网络请求在离线回归中一律替身（monkeypatch 对应函数）。`make check` 会给回归子进程设置测试专用 `JWT_SECRET_KEY`、空 `DEEPSEEK_API_KEY`、指向本机不可达端口的 `DEEPSEEK_BASE_URL`，即使本机 `.env` 有真实 Key 也不会联网、不耗额度。
判据：断网后 `make check` 结果不变。

## 7. 一键运行与通过判定

```bash
make check                          # macOS / Linux
backend/.venv/bin/python scripts/check.py   # 等价；Windows 用 backend\.venv\Scripts\python.exe
```

子项：openspec 严格校验、分层检查、密钥扫描、前端 `tsc --noEmit`、全部离线回归。**任一子项非零退出即不通过，失败即阻断合并。**
当天让门禁变红的人负责当天修复；不得为了变绿而删断言、放宽检查或跳过子项。

## 8. 变更时的要求

- 每次变更至少补上与其新场景对应的检查。
- 修复缺陷：先写一条能复现缺陷的检查（此时为红），再改代码使其变绿，保留该检查。
- 认为某条断言本身写错了：改断言，并在变更的验证记录里写明原因（示例：`check_lesson_prep.py` 的日志处理器断言，见 `docs/lesson-07/`）。

## 测评判定口径

| 判定词 | 含义 |
| --- | --- |
| 被当成成功 | 负向用例拿到 2xx，或数据发生了约定外的变化，或返回了不该返回的数据 |
| 被放行 | 权限类用例拿到了不该拿的数据，或写操作实际生效 |
| 被误拒 | 合法请求没得到成功响应，或约定的副作用没有发生 |
| 未处理故障 | 500、响应含堆栈或异常原文、只有“系统错误”这类无信息文案 |

本系统按 HTTP 状态码判成败（未使用独立错误码）：成功 2xx；参数非法 400/422；未登录 401；无权限 403（跨班也是 403，见安全规范例外）；不存在 404；冲突 409；依赖不可达 503。

## 违反时

失败即阻断。规范与用例冲突时先改规约或规范，再改用例，不由执行者自行跳过。
