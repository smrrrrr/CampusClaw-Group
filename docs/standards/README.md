# 工程规范：从这里开始读

这组文件用于回答两个问题：**AI完成的功能是否符合规约？代码实现是否符合工程规范？** 写了文档只是有了判据；只有相应检查和证据，才能判断本次任务是否通过。

## 1. 先分清三个词

| 名称 | 回答什么 | 放在哪里 |
| --- | --- | --- |
| 规约 | 给谁用、完成什么、失败时怎样、哪些不做 | `openspec/specs`及具体变更的Scenario |
| 规范 | 怎样写代码和交付，哪些边界不能破坏 | 本目录01–08 |
| 验证记录 | 哪项实际检查过、用什么方法、得到什么结果 | 变更validation和docs中的记录 |

**推荐读法：** 先看根目录 [AGENTS.md](../../AGENTS.md) → 按下表找与任务有关的规范 → 执行检查并留证。每份正文按“什么时候读、具体要求、怎么检查、现状/例外”组织；不用每次从01读到08。

新增保证项先看 [待讨论的验收约束](待讨论的验收约束.md)。它是讨论稿，本轮不增加检查器或改变产品功能。

## 3. 读完之后怎样验收

每条新增/修改规则写“触发条件 → 必须/禁止的动作 → 检查方法 → 预期值 → 失败处理 → 证据”。数值来自当前接口契约或明确标记为验收目标；不用“大量、较快、充分、安全”代替判据。

Scenario 写清 GIVEN（账号、班级、状态、依赖与数据）/ WHEN（操作）/ THEN（HTTP、可见内容、数据及文件变化）。正常/失败/边界分组，至少覆盖参数非法、无权限、资源不存在、依赖不可达；不适用项写理由和替代检查，不编造接口。

执行命令从仓库根目录开始。Windows 使用上述 venv Python；macOS/Linux 使用 `backend/.venv/bin/python` 或 `make check`。模型、网络与人工检查不冒充离线门禁，见 [课程核查记录](../lesson-07/checklist-2026-11-04.md)。

## 4. 工具如何读取

| 工具入口 | 本仓库文件 | 格式与核验 |
| --- | --- | --- |
| Codex | `AGENTS.md` | 根目录 Markdown 常驻规则；不用技能 YAML 包裹；本会话已收到，不代表新会话已验 |
| Claude Code | `CLAUDE.md` | 保持 `@AGENTS.md` 导入；独立会话须复述实际读取路径 |
| Trae | `.trae/rules/project_rules.md` | `description` + 布尔 `alwaysApply: true`，无路径过滤；只指向总纲，实际自动加载另验 |
| 场景流程 | `.claude/skills/*/SKILL.md` | `name` 与目录一致、`description` 写明触发条件；AGENTS 明确路径。其他工具按路径阅读，不声称自动发现此目录 |
| OpenSpec 技能 | `.agents/skills/`、`.trae/skills/` | 使用现有工具入口；不自动执行 apply、归档或勾选任务 |

`globs` 适用于按路径筛选的规则；总纲必须常驻，不能只在命中某个业务目录时加载。普通规范 Markdown、CLAUDE 导入与 SKILL.md 各用自身格式，不把一套 frontmatter 强塞给所有文件。
