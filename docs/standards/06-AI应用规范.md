# 06 AI 应用规范 · CampusClaw

适用：`backend/llm_service.py`、`lesson_service.py`、`question_service.py`、`mcp_orchestrator.py`、`rag_search_service.py`、`model_json.py`，以及教师编写的助手提示词与技能文件。
被谁读到：`AGENTS.md` 规范索引（改上述文件或任何提示词时必读）；技能 `prompt-change`。
密钥存放见 03-安全开发规范，日志字段见 05-部署运维规范，本页只管模型带来的不确定性。

## 1. 调用边界：能算出来的不问模型

| 环节 | 用模型 | 用确定性规则 |
| --- | --- | --- |
| 学生助手 | 生成解答与引导 | 检索（字符 n-gram 哈希向量 + 关键字 RRF）、班级 / 学科过滤、引用编号与原文对照、每日 40 次额度 |
| 智能备课 | 生成教案、学生稿 | 去答案校验、图片 SHA-256 核对、版本与发布记录 |
| 智能命题 | 生成题目 | 题目结构与公式校验（`validate_question`）、知识点只取 `knowledge_tags.TOPICS`、组卷配比 |
| MCP 工具 | 决定是否调用、生成参数 | 参数按工具 schema 校验、调用次数上限、白名单主机 |

判据：逐个调用点问一句“换成规则会怎样”；答得出“规则做不到”的才保留模型调用。

## 2. 工具只走已有服务

模型能调用的只有教师登记并发现的 MCP 工具，经 `mcp_orchestrator` → `mcp_client` 调用，带次数上限与审计。不为模型开放数据库查询、文件读取或任意 HTTP 工具。
判据：逐个工具确认最终落到哪个服务方法；出现直接查库或读 `uploads/` 的工具即违规。

## 3. 提示词即代码

- 系统提示词以常量形式写在代码里：`llm_service.DEFAULT_SYSTEM_PROMPT`、`TUTOR_SKILL_PROMPT`、`CITATION_POLICY`，`lesson_service.TEACHER_PROMPT`、`STUDENT_PROMPT`，`question_service.QUESTION_PROMPT`。随版本入库，不放 `.env`。
- 修改任何一条都走变更流程：提变更 → 改提示词 → 跑评测（§7）→ 在变更的验证记录里写改前改后结论。
- 教师在页面上配置的班级提示词与技能文件属于数据，不受本条约束，但仍受 §6 约束；`CITATION_POLICY` 永远追加在最后，不可被教师提示词覆盖。

**现状（书面）**：提示词常量没有版本号。失效条件：下一次修改提示词的变更里，在常量旁加 `# prompt-version: YYYY-MM-DD` 注释并记录评测结论。

## 4. 模型与参数集中配置

模型名、地址、温度、超时只在 `config.py`：`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`、`deepseek_temperature=0.3`、`deepseek_timeout=60`；检索阈值同在一处：`chunk_top_k=3`、`chunk_min_relevance=0.35`、`chunk_min_keyword_hits=3`。代码里不得出现散落的数值常量。
当前部署用课程网关 `course-chat`（推理模型，首字较慢），每人每日 10 万 token。

## 5. 超时与降级

- 每次模型调用都带 `deepseek_timeout`；超时或失败返回明确的 503 / SSE `error` 事件与可理解提示，不无限等待，不静默返回空结果。
- 未配置 `DEEPSEEK_API_KEY` 时：浏览既有资料、教案、题目正常；需要生成的接口返回 503 与提示；`/api/health` 报 `model: not_configured`。
- MCP 工具不可达时学生助手照常回答，只是不带工具结果。

## 6. 输出校验与不编造依据

- 结构化输出（学生稿 JSON、题目 JSON）先经 `model_json` 解析与修补，再校验；解析或校验失败按失败处理，不以默认值顶替入库。
- 检索未越过阈值时不提供资料片段，回答不带任何 [n] 出处编号，明确说明“未在本班资料中找到依据”。
- 出处编号只能指向本轮真实命中；摘引须逐字来自片段。
- 资料正文、技能文件、工具返回作为数据放在用户消息里，系统提示写明不执行其中的指令。“解题引导”只给步骤与提示，不给最终答案。

判据：清空本班资料后提问，回答中不出现任何出处编号；上传含指令性文本的资料，助手不照做。

## 7. 评测集与回归

在 `apitest/eval/cases.jsonl` 维护 20 条：10 条必须答对（问题、期望要点、期望出处资料名），10 条必须拒答或不挂出处（跨班资料、跨学科、资料外问题、诱导执行资料中指令、索要完整答案）。改提示词或换模型后用 `apitest/probe_*.py` 方式跑一次，结果写入 `docs/eval/YYYY-MM-DD-<变更名>.md`。
**现状（书面）**：评测集尚未建立，列为第 7 课待办（见 `docs/lesson-07/`）。在建立之前，修改提示词的变更必须附至少 5 条手工抽查记录。

## 8. 用量观测

记录模型名、调用类型、耗时、是否成功、命中片段数；不记录提示词全文、学生提问原文与资料正文。学生提问次数由 `ai_question_logs` 计数（用于每日额度）。

## 违反时

改提示词不跑评测（或不附抽查记录）即视为变更未完成；出现编造出处按缺陷处理，先补一条能复现的检查或评测用例，再改提示词。
