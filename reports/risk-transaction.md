# 高风险检查：事务

| 项目 | 内容 |
| --- | --- |
| 用什么手段查 | check_async_grading的B3故障注入、B2补投及B4租约检查；真实代理进程故障实验 |
| 查什么 | 一次教师初批含两份提交，第二条任务插入时抛出数据库错误；代理确认或消费者执行中断 |
| 判据 | HTTP503且不泄露异常；任务与发件箱标记均0，已有提交与分数不变；代理故障后自动补投，中断执行由新租约恢复，旧租约不能写回 |
| 结果证据 | [offline-result.json](async-grading/offline-result.json) B2/B3/B4；[real-broker-result.json](async-grading/real-broker-result.json) B1/B2/B4 |

本项目保留“教师点击才初批”，学生提交不自动创建任务；因此事务边界是“本次教师批改任务+发件箱”，不是把已有学生提交倒退重写。模型外呼不占写事务，AI评分与任务完成在同一短事务提交，随后才确认消息。

复跑使用完整 `scripts/check.py` 与真实队列复现脚本。检查对应的是合成数据上的实际失败/恢复，不能推断所有其他业务事务已覆盖。
