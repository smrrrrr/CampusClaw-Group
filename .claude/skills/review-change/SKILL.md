# 按规范评审一次变更

输入：变更名，以及待审的提交范围或工作区改动（`git diff main...HEAD`）。

1. 读 `docs/standards/08-评审与完成定义规范.md`，以及改动涉及的其他规范（按 `AGENTS.md` 索引）。
2. 规约覆盖：列出变更 spec 中每个 Scenario → 对应的检查名（`apitest/check_*.py`）。没有对应检查的列为“未覆盖”。
3. 授权：每个新增或修改的读写接口，确认使用了 `deps.py` 依赖、按 ID 先取行后校验归属、没有采信请求里的 `class_id` / `role`；越权检查是否成对存在。
4. 数据：表结构改动是否可重跑、是否写了回滚动作、是否同步模型注释与主规约。
5. 提示词：是否有评测或抽查记录（06 规范 §7）。
6. 规范一致性：分层（`python scripts/check_layering.py`）、接口命名、错误响应 detail 是否泄露内部信息、日志是否记录敏感内容、重复代码。
7. 运行 `make check`。
8. 按完成定义五条逐条给出“满足 / 不满足 + 证据（文件:行号或命令输出）”。不满足的任何一条都给出结论“不可合并”。

产出：评审结论表（可贴进 PR 或变更的 validation.md）。只报告问题，不自行修改被审代码。
