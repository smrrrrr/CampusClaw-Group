# 设计

## Context

正式报告保留在仓库根目录 report.md，细节进入 reports/，Markdown 是提交源。现有支撑材料跨多个日期、系统和提交，必须保留各自的证据范围。

## Goals / Non-Goals

目标是六节报告、七类可查清单、至少三份真实评审、可复跑的三条高风险检查、可核验的门禁链路与录屏指引。

## Decisions

1. 将历史总报告原样转存，新增当前状态入口，历史记录不改时间。
2. 规则仍以 AGENTS.md 为单一入口，仅展开已有七类问题与对应命令，不新增虚假的覆盖率或性能门槛。
3. 测试使用现有脚本、临时 SQLite 和模型/MCP 替身。完整门禁保留全部子项。新证据保存原始输出、退出码、时间、基线和受测源码摘要。
4. 新版要求提前提交录屏。演示用本机独立环境，先跑报告命令，再登录展示学生提交和教师初批。学生提交 200，教师初批 202，资料跨班 404，任务权限 403。
5. PDF从 report.md 生成。布局检查、文件路径检查与源文件摘要记录在验证文档；输出作为阅读副本，平台以同一份 report.md 为准。

## Risks / Trade-offs

当前草稿基于 PR #6，正式交付还需评审与主干合并。录屏待录制和上传，填写下载地址后需同步校验 Markdown 与 PDF。

## Verification

验证六节顺序、所有引用的存在性、贡献与PR来源、完整门禁、三查脚本退出码与具体断言，核对PDF页数和逐页可读性。执行详情记入 validation.md，尚未验证时不写PASS。
