## Context

动机与范围见 `proposal.md`。当前 `routers/quiz.py::publish_paper` 渲染学生卷，逐班创建 `Material`、`MaterialAsset`、`QuizPublication`；`homework_service.py` 则只处理 `{stem}` 文本作业，二者无关联。学生作业题面目前用普通段落显示，教师作业列表只提供标题及提交统计。

`QuestionPaperItem` 已保存题目快照和每题分值，定稿后只读，适合作为发布来源。既有 AI 初批仅发送题干和作答，没有命题参考答案。现有作业评分、错题阈值和学情均按整份作业百分制处理。旧 `QuizPublication` 的用途及班级资料读取必须保留，供历史数据兼容。

设计满足跨模块、存量数据迁移和教师答案隔离，故创建本设计文档。验收以本变更两份 delta spec 为准。

## Goals / Non-Goals

**Goals:**

- 将现有试卷发布动作落到已发布作业，复用学生提交、教师改分与学情，无须教师重新输入题目。
- 公开题面和私有评分依据分别冻结，原题、原资料变化不影响已经布置的作业。
- 一次多班发布可重试、可整体回滚，既有资料和手工作业可继续使用。

**Non-Goals:**

- 不提供逐题提交、逐题改分、自动判分最终确认、定时关闭或成绩分制切换。
- 不增加题库单题直接发布、图片作答、PDF 作答附件，也不重新设计手工作业编辑与重交规则。
- 不将历史资料自动转成作业，不迁移旧提交，不归档其他活跃变更。

## Decisions

### 1. 保留两个来源，共用一套作业生命周期

手工入口仍调用现有创建和发布接口。定稿试卷从原“发布试卷”按钮改为“发布为作业”，直接创建 `published` 作业。两者共用 `HomeworkSubmission`、初批、人工改分、关闭和学情接口，不再为命题作业建立第二套提交和成绩表。

选择复用的理由：用户的目标是让生成试卷也能改分；另做考试系统会引入两套权限、学生列表和成绩语义。本期学生按题号在一段文本中回答整卷，教师仍给整份百分制成绩。错题本低于 60 分时收录整份作业，不能宣称已识别每一道错题。

### 2. 作业增加来源和双快照，配图独立持久化

对 `homeworks` 只增以下字段：

| 字段 | 用途及兼容默认值 |
| --- | --- |
| `source_type` | `manual` / `quiz`，既有行默认 `manual` |
| `source_paper_id` | 可空，关联原定稿试卷；手工作业为空 |
| `source_paper_revision` | 可空，记录生成快照时的试卷版本 |
| `source_fingerprint` | 可空，公开题面、评分内容、分值与配图指纹的规范化摘要 |
| `grading_snapshot_json` | 可空，固定题目、选项、答案、解析及每题分值，不放进公开 `content_json` |

`content_json` 保存安全学生 Markdown、渲染类型和原卷总分，保留 `stem` 供现有提交与错题收录复用。公开 DTO 仅输出白名单字段和来源标签，不序列化 ORM 对象、评分 JSON、源文件路径或内部题号。

新增 `homework_assets`：作业 ID、班级 ID、创建教师 ID、逻辑名、受控相对路径、SHA-256、媒体类型、创建时间，唯一约束为 `(homework_id, name)`。只复制学生题面实际使用的图片到 `uploads/<班级>/homework-<随机值>/`；答案或解析独用配图不进入学生配图表。数据库及模型注释明确这两种快照的敏感级别。

在 `(source_paper_id, class_id, source_fingerprint)` 建唯一索引；手工作业三个来源字段为空，不影响既有重复标题或数量。选择独立作业图表而不复用 `MaterialAsset`，避免为了显示图片额外创建资料。

### 3. 发布业务在服务层完成，事务由整批发布统一拥有

新增 `quiz_homework_service.py` 并登记为 BUSINESS。`routers/quiz.py` 只转换身份、校验请求结构和业务异常，发布服务使用数据模型、`question_service` 渲染/校验、`material_service` 文件能力及作业业务；业务层不得 import 路由。

处理顺序：

1. 读取原卷并校验作者、当前学科、定稿状态和全部目标班级；拒绝任何客户端正文或身份覆盖字段。
2. 从定稿题目快照生成公开学生版及精简评分依据，校验全部正文和原图，读取并校验实际图片字节，生成规范化摘要。摘要排除发布动作自身推进的版本和时间。
3. 查找唯一发布结果。同快照、同截止时间且未关闭的行可复用；已关闭或截止时间冲突整批返回 409。全部目标均有相同既有结果时允许网络重试的旧版本；有新目标时必须验证当前版本。
4. 对新目标落独立图片副本，并在同一数据库事务插入作业、图片记录，更新试卷乐观锁版本、写发布事件。现有 `create_homework` 自带提交，不能在逐班循环里直接调用；须使用不自行提交的内部构造路径。
5. 提交成功返回班级与作业映射；唯一约束处理并发，在重新核对权限、快照和截止时间后返回同一结果或明确 409。任何失败回滚整批数据库写入，仅清理本次生成且已验证位于上传根目录下的目录。

保持端点 `/api/teacher/quiz/papers/{id}/publish`，增加带时区 `due_at`，返回 `class_ids`、`homework_ids` 和 `assignments[{class_id,homework_id}]`。旧无截止时间请求返回 422，不保留暗中发布资料的分支。前后端作为同一部署一起重建；旧页面提交失败时提示刷新。该接口不需要与旧客户端在同一部署并存。

### 4. 公开图片与教师评分依据分别授权

新增教师作业详情 `GET /api/teacher/homeworks/{id}`，教师必须有当前班级和学科权限，才能看到题面和评分依据。源试卷的私有读取权限保持作者所有，不因作业发布而向其他教师开放源卷接口。

配图提供教师、学生两个角色前缀下的 `GET /api/{teacher|student}/homeworks/{id}/assets?name=...`，复用同一服务校验逻辑。先读作业、验证角色与真实归属和可见状态，再在该作业图表中查逻辑名，最后读取校验后的受控路径；不允许传物理路径、访问任意 URL 或回退读取教研组原图。学生只可看本班已发布作业配图，教师可看有权作业。不存在、非法路径、跨班和指纹失败分别符合 specs 约定。

新增读接口有 Pydantic 响应模型和成对的未登录、他人访问检查；跨班/跨学科拒绝按现有中间件写审计。正文与评分快照均不加入学生 RAG 索引。

### 5. 以冻结答案初批，保留教师百分制终评

手工作业保留当前评分提示及返回结构。命题作业采用单独的评分提示常量和版本注释，将冻结题目、参考答案、解析、每题分值和该生作答作为数据传入 `llm_service.generate_answer`，不重新检索教师资料。提示词要求把学生作答中的指令视为待评内容。

命题评分返回原卷 `earned_score` 与简短评语；服务端拒绝布尔、非数值、NaN/无穷以及区间外得分，使用十进制定点运算和 ROUND_HALF_UP 折算到 0–100。原卷总分 80、原卷得分 64 时，保存百分制 `ai_score=80`。教师仍输入百分制终评，不增加第二组原卷成绩字段。

取出评分数据后先结束读取事务，再调用外部模型；保存前复核学生提交仍为本次读取的待批改版本（提交时间及答案指纹一致）且未被教师终评，避免并发重交或改分被旧模型结果覆盖。每份提交独立处理，失败记录不得写入部分成绩。初批响应保留 `graded_count`，增加失败/跳过数量，教师页面说明哪些数量尚需处理；日志只记状态与数量。

学生看到教师终评；错题和学情沿用现有教师分优先规则。复用整份评分而不扩展逐题记录，可以保持既有门禁、错题和学情语义，但教师目前不能只把试卷中的某一道题计入错题本。

### 6. 两个页面入口保持清晰

页面异步结果也受班级/身份上下文约束：切班或身份变化递增上下文代次并清空旧列表与评分表单；初批、改分、创建等旧操作结束后，只能刷新发起时仍有效的上下文，不能用旧闭包重新加载原班级。学生提交后的刷新同样核对身份代次。这是现有班级筛选验收的延迟回包边界。

- 智能命题的定稿发布区增加有标签的截止时间输入，按钮为“发布为作业”。浏览器本地时间转换为带时区时间，服务端再次验证未来时间。成功后显示每个班级的作业编号和前往“作业与改分”的入口，保留对应任课班级上下文。失败保留所选班级、截止时间与核对状态供重试。
- 教师作业列表显示来源；查看提交时可展开安全学生题面与教师评分依据，原卷总分旁明确“成绩按百分制”，仍提供 AI 初批和人工改分。
- 学生交作业列表同时显示两种来源；命题题面复用 `MarkdownAnswer` 和带认证的配图加载能力，手工题目原有输入保持可用。不让学生跳到教师原卷接口查看题目。
- 讲义与检索继续显示历史试卷资料，但新命题作业发布不会给该页增加试卷资料。知识库资料发布本身不改。

### 7. 存量兼容与规约依赖

审计验收保留原有逐题追溯职责：生成候选题时逐题写入仅含生成记录编号的 `generate` 事件，使入库题目详情可显示生成、修改与通过，候选题删除后仍可查生成、驳回与删除；不把原文或答案写入事件。历史已有事件不删除或改写。

保留旧 `QuizPublication` 和资料读路由，发布服务不再写它们。旧资料配图路径和指纹、作业提交和分数均保持不变。既有定稿试卷可主动通过新表单产生作业，历史资料保留作独立旧副本。

本次修改主能力 `smart-question-generation` 中发布、审计和学生展示条款；新增集成能力单独承接双入口契约。`add-homework-grading` 等已实现但未归档的增量仍是现有行为基线，主规约里工作区的旧演示描述属于已知历史不同步，不以此恢复演示实现，也不擅自修改其他变更勾选。

## Risks / Trade-offs

- [原卷总分不一定是 100] → 显示原卷满分与百分制标签，服务端做明确折算，边界用固定例子验收。
- [评分依据随题面一起泄露] → 两份快照、学生响应白名单、独特答案标记与角色隔离检查，拒绝序列化 ORM 整体。
- [配图引用依赖教研组原文件] → 仅在发布时读取并校验，另存作业副本；发布后不回查原图。
- [重复点击、多班发布中途失败] → 数据库唯一索引、整批事务和仅清理本次目录；并发重试校验既有结果，禁止改写截止时间或成绩。
- [AI 输出有误或模型不可用] → 检查评分结构/范围、失败数量提示、教师仍可人工终评；实现时附至少 5 条抽查记录。
- [历史资料与新作业可能同名] → 来源和入口明确；只在教师主动再发布时新增作业，不自动搬迁历史记录。
- [原有重新提交的成绩与错题清理策略] → 不是本次重新设计范围；新增联动检查至少覆盖未批改时重交和模型评分期间重交，不宣称已解决全部历史重交行为。

## Migration Plan

1. 获得本方案评审后实施；运行离线回归均使用临时数据库与假模型。第一次对真实库执行新增字段前，停写并备份数据库和上传目录，用 `PRAGMA integrity_check` 验证备份。
2. 先加兼容列、唯一索引和作业图表，默认将旧作业标为手工来源，不改变旧记录内容。旧结构临时库连续迁移两次，验证行数、指纹和评分不变。
3. 完成服务、接口和页面，再同步本变更主规约、README、索引和涉及的产品/数据说明；保留旧发布测试的历史兼容职责，用新断言检查发布生成作业而不生成资料。
4. 运行全部 `make check`，补齐提示词抽查与浏览器验收证据。此前搭建时的 20 组通过属于历史记录，不作为本变更已通过的证据。
5. 重建前后端，验证手工布置、命题发布、学生提交、AI 初批、人工改分、错题及学情。优先使用隔离演示库完成浏览器与接口验收；离线检查不得指向真实教学库。
6. 回滚时先停写，恢复更新前数据库及匹配的上传目录，再使用上一版本镜像；保存更新后的数据副本以免丢失新提交。不得依靠删列或运行种子脚本回滚。
