## MODIFIED Requirements

### Requirement: 试卷定稿与分班发布

作者 MUST 显式定稿草稿试卷（`POST /papers/{id}/finalize`，带 `revision`）。定稿后试卷只读；如需修改，用“复制为新草稿”生成新试卷。

新发布（`POST /api/teacher/quiz/papers/{id}/publish`）MUST 创建作业，请求包含 `revision`、`reviewed=true`、1–30 个目标 `class_ids` 和带时区的 `due_at`。截止时间 MUST 晚于服务端当前时间；缺失或格式非法返回 422，截止时间已过返回 400。教师身份、学科与任教班级以当前数据库为准；非作者或跨学科访问源试卷按原有边界返回 404，任一目标班级越权整批返回 403 并审计。草稿试卷或版本冲突返回 409，未核对学生卷返回 400。

学生卷 MUST 由服务端从定稿题目快照渲染，不接受客户端提交正文、参考答案或身份学科。学生卷包含标题、时长、原卷总分，按题型分节的连续题号、每题分值、题干和选项，填空空位及解答题作答横线。学生卷 MUST NOT 含答案、解析、出处、S 编号或内部题号，且 MUST 通过学生版去答案与链接校验；语义正确性仍由教师核对。

每个目标班级 MUST 获得独立的已发布作业，来源标识为智能命题、学科为教师当前学科、截止时间为请求中指定的截止时间。成功响应 MUST 包含 `class_ids`、`homework_ids` 以及可核对的班级与作业对应关系。新发布 MUST NOT 创建班级资料、旧式试卷资料发布记录或检索切片，作业题面及教师评分依据均不得进入学生助手检索索引。

公开题面与私有评分依据 MUST 在发布时冻结。只复制学生版题面实际使用的原图，复制前核对指纹；缺失或不一致返回 409，整批不得创建部分作业。相同试卷、班级和发布快照指纹具有唯一发布结果；指纹须同时覆盖学生题面、评分内容、分值及配图指纹，不使用发布动作导致变化的版本计数作为去重依据。

对于同一快照、相同且仍有效的截止时间、尚未关闭作业的重复或并发发布，MUST 返回原作业编号，不重置提交、评分或截止时间；混合新旧目标班级时仅创建尚不存在的作业，并保证整批事务。重复发布使用不同截止时间，或已有对应作业已关闭时，MUST 返回 409，说明需复制试卷开始新一轮，不覆盖既有作业。网络重试的相同已完成发布即使携带原请求版本也 MUST 可复用原结果；创建新目标仍须通过当前版本校验。

任何班级、文件或数据库写入失败 MUST 整批回滚并清理本次新建文件，不影响既有作业与文件。教师仍可下载源试卷答案卷（`GET /papers/{id}/answer-key`），该能力保持作者私有。历史发布到资料页的试卷及原图 MUST 原样保留，不自动迁移；教师可主动为原定稿试卷新增作业发布。

#### Scenario: 发布到两个任教班级

- **WHEN** 教师核对定稿试卷，指定未来截止时间后发布到本人任教的 101、102 班
- **THEN** 两班交作业列表各出现一份独立命题作业，教师可查看提交与改分；两班资料和检索切片数量不增加，响应班级与作业编号一一对应

#### Scenario: 批次混入非任教班级

- **WHEN** 发布目标包含合法的 101 班和非任教的 201 班
- **THEN** 返回 403 并审计，101 班也不创建作业，不遗留本次配图副本

#### Scenario: 草稿试卷发布

- **WHEN** 教师对尚未定稿的试卷调用发布
- **THEN** 返回 409，提示先定稿，不创建作业

#### Scenario: 发布身份边界

- **WHEN** 未登录请求发布、学生请求发布，或教师访问非本人/其他学科的源试卷
- **THEN** 分别返回 401、403、404，不新增作业、资料或文件，不泄露源试卷内容

#### Scenario: 未确认核对或版本冲突

- **WHEN** 创建新目标作业时未确认学生卷核对，或携带落后的试卷版本
- **THEN** 分别返回 400 或 409，不创建任何作业，不覆盖既有发布

#### Scenario: 重复发布

- **WHEN** 同一定稿试卷、班级、快照和截止时间被重复请求、网络重试或并发发布
- **THEN** 返回同一原作业编号，数据库恰有一份作业，已有提交及评分保持不变

#### Scenario: 混合已有和新目标班级

- **WHEN** 101 班已有同快照同截止时间的作业，教师以当前版本再向 101、102 班发布
- **THEN** 复用 101 班作业，只为 102 班新增作业，返回两班对应编号

#### Scenario: 重复发布更换截止时间或遇到已关闭作业

- **WHEN** 同一快照已有作业但新请求改了截止时间，或原作业已关闭
- **THEN** 返回 409 并提示复制试卷开始新一轮，原作业、提交和分数不变，批次其他新班级也不写入

#### Scenario: 发布参数边界

- **WHEN** 请求缺少截止时间、使用无时区时间、班级数为 0 或 31，或截止时间不晚于当前时间
- **THEN** 缺失、类型、时区或数量问题返回 422，过期时间返回 400；均不创建作业

#### Scenario: 原图校验或文件写入失败

- **WHEN** 学生题面原图缺失、指纹不符，或第二个班级写入文件/记录失败
- **THEN** 图校验失败返回 409，其余写入失败返回不含路径的中文错误；整批无新增作业或资料，本次新文件被清理，既有文件不变

### Requirement: 命题审计记录

以下操作 MUST 各写入一条 `question_events`：

- 生成成功 / 失败
- 候选题修改、通过、驳回、删除
- 复制为新候选
- 下架 / 恢复
- 组卷、草稿修改、定稿、复制试卷、发布

每条记录包含：操作人、学科、对象类型（generation / item / paper）、对象编号、动作、时间、明细。明细内容视动作而定：修改前后的内容指纹、驳回原因、发布班级与作业编号（历史记录保留原资料编号）、生成的通过 / 未通过数量。

记录 MUST NOT 含模型 Key 或完整提示词。题目或试卷删除后，其审计记录 MUST 保留。可见范围与题目一致：

- 题目详情显示该题的事件历史。
- `GET /api/teacher/quiz/events` 返回本人的操作记录。

#### Scenario: 查看入库题目的复核历史

- **WHEN** 本学科教师查看一道入库题目的历史
- **THEN** 依次显示生成、作者修改（含前后指纹）、通过三条事件及其时间与操作人

#### Scenario: 删除候选题后追溯

- **WHEN** 作者删除一道已驳回的题目
- **THEN** 题目读取返回 404，作者的操作记录中仍可查到其生成、驳回、删除事件

#### Scenario: 作业发布审计

- **WHEN** 教师成功将定稿试卷发布为作业
- **THEN** 发布事件记录源试卷、目标班级与作业编号，不包含参考答案、学生作答、评分依据正文或密钥

### Requirement: 题目内容显示

前端 MUST 用共用的 Markdown + KaTeX 渲染器（`MarkdownAnswer`）显示题目内容，包括：题库与待复核列表中的题干；题目详情中的题干、选项、答案与解析；草稿与已定稿试卷中的题干；学生卷预览；学生交作业中的命题作业及历史已发布试卷资料。编辑模式的输入框 MUST 显示原文，不做渲染。

选择题的每个选项 MUST 与题干一样经过渲染，公式 MUST NOT 以 `$…$` 源码显示；选项标签与内容 MUST 显示在同一行（选项含块级公式时除外）。

题目详情的答案：填空题与解答题的答案 MUST 经过同一渲染器，公式 MUST NOT 以 `$…$` 源码显示；填空题多个空位的答案按顺序用「、」分隔。单选、多选题的选项字母与判断题的「正确 / 错误」MUST 保持纯文本显示。答案卷下载的 Markdown 不在本需求范围内。

填空空位：渲染前，正文中连续 4 个及以上的下划线（与后端空位判定一致）MUST 转为按字面显示、不参与 Markdown 强调解析的形式，长度与数量不变。以下内容 MUST NOT 改动：代码块与行内代码、`$…$` / `$$…$$` 公式内部、尖括号自动链接、前面已有反斜杠的下划线、整行只有下划线的行（学生卷解答题作答横线与分隔线保持横线显示）。该规则作用于共用渲染器，因此在 AI 回答、讲义与学生稿预览中同样生效。

本需求只约束显示：MUST NOT 修改已保存的题目、试卷快照或学生卷 Markdown，不改变接口与服务端校验。

#### Scenario: 多空位填空题显示

- **WHEN** 教师在待复核列表或详情中查看题干为 `…则 $\overrightarrow{EF}$ 的坐标为____，____，____。` 的填空题
- **THEN** 页面显示 3 个空位，无加粗或斜体，公式正常渲染

#### Scenario: 空位与公式下标共存

- **WHEN** 题干同时含 `$ABCD-A_1B_1C_1D_1$` 与空位 `____`
- **THEN** 公式下标正常渲染，空位按字面显示，`.katex-error` 数为 0

#### Scenario: 选项含公式

- **WHEN** 教师打开选项为 `$(1,2,2)$`、`$(1,-2,2)$` 等的单选题详情（待复核或题库）
- **THEN** 四个选项都以数学符号渲染，每项「A. 内容」在同一行，页面 `.katex-error` 数为 0

#### Scenario: 填空与解答题答案含公式

- **WHEN** 教师打开答案为 `["$\frac{\sqrt{15}}{5}$"]` 的填空题详情，或答案为 `$\frac{\sqrt{3}}{3}$` 的解答题详情
- **THEN** 答案以数学符号渲染，不显示 `$` 源码，页面 `.katex-error` 数为 0

#### Scenario: 多空答案与选择判断答案

- **WHEN** 教师打开答案为 `["1","1","-1"]` 的填空题，以及单选、多选、判断题的详情
- **THEN** 填空答案显示为 `1、1、-1`；选择题显示选项字母（多选用「、」分隔），判断题显示「正确」或「错误」，与修改前一致

#### Scenario: 编辑答案时显示原文

- **WHEN** 教师在待复核详情中点击修改
- **THEN** 答案输入框显示原文（含 `$…$`），不做渲染

#### Scenario: 解答题作答横线不变

- **WHEN** 教师预览含解答题的学生卷
- **THEN** 作答区仍显示为横线，不变成一串下划线文字

#### Scenario: 学生端打开已发布试卷

- **WHEN** 学生在交作业中打开含多空位填空题的命题作业，或预览历史试卷资料
- **THEN** 每道填空题的空位数与发布时题干一致，两种入口均正常渲染

#### Scenario: 代码中的下划线

- **WHEN** 渲染内容在行内代码或代码块中含 `____`
- **THEN** 代码原样显示，不出现多余的反斜杠

### Requirement: 学生卷选项排版

服务端渲染学生卷时，每道题以 `n. 题干` 开头，记题号前缀 `n. ` 的长度为该题的缩进宽度。题干与选项的续行 MUST 按该宽度缩进，使其留在同一列表项内；题号到两位数时同样适用。

选择题（单选、多选）的选项 MUST 与题干分段，并按 A–D 顺序各占一行显示：

- 选项文本都不含换行时，选项之间用 Markdown 硬换行连接；
- 任一选项文本含换行时，每个选项单独成段。

判断题、填空题的输出不变；解答题的作答横线不变。本需求只改学生卷正文的排版，不改题目快照，也不改答案卷。已发布的班级资料及命题作业快照 MUST NOT 被改写。排版改变后，新发布按包含学生卷排版的发布快照指纹处理，不覆盖旧作业。

#### Scenario: 选项各占一行

- **WHEN** 教师预览一份含 2 道单选题的已定稿试卷
- **THEN** 每道单选题的题干单独一段，A、B、C、D 四个选项各占一行、与题干不在同一行，选项中的公式正常渲染，页面 `.katex-error` 为 0

#### Scenario: 第 10 题以后

- **WHEN** 试卷有 12 道单选题
- **THEN** 第 10–12 题的选项仍显示在各自题目下，题号 1–12 连续，选项不会脱离所在题目

#### Scenario: 选项含块级公式

- **WHEN** 某单选题的选项 B 含两行的 `$$…$$` 公式
- **THEN** 四个选项各自成段，块级公式正常渲染，后续题号连续

#### Scenario: 学生端打开新发布的试卷

- **WHEN** 教师将一份含选择题的定稿试卷发布为作业，学生在交作业中打开
- **THEN** 选择题选项各占一行，且学生卷不含答案、解析与出处

#### Scenario: 已发布资料不被改写

- **WHEN** 变更前已发布的试卷资料被学生再次打开
- **THEN** 资料内容与发布时一致
