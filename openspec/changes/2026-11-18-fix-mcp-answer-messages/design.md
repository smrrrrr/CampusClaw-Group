## 消息边界

工具决策使用独立的消息列表。每轮先保留模型提出的工具调用（以及供应商返回的思考字段），再按调用 ID 追加对应结果。成功、拒绝和失败的调用均有对应消息。候选校验、授权、结果安全检查及审计仍由原工具执行流程负责。

最终流式回答沿用原始对话。只把通过安全检查的工具结果附在当前用户消息的数据段，不携带工具决策的临时协议消息或思考字段。工具失败仍按既有规则降级。模型异常日志只记录失败类型和可判定的 HTTP 状态码。

## 验证与部署

用现有 MCP 集成检查验证后续决策的消息配对和最终用户消息内容。新增输出仍通过现有构建配置进入后端镜像。真实验证以新镜像启动后同一轮学生提问同时产生成功的工具审计和完整流式回答为准。模型密钥和 MCP 登记仍依赖本机配置。
