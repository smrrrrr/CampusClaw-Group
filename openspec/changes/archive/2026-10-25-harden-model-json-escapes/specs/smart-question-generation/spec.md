## MODIFIED Requirements

### Requirement: 结构化输出与逐题校验

模型 MUST 被要求只输出一个 JSON 对象：`questions` 为题目数组，`gaps` 为无法给出依据的空位数组，并被提示 JSON 字符串里每个 LaTeX 反斜杠都写成两个。外层若包有单个代码围栏，MUST 先剥除再解析。

提示词 MUST 要求 `knowledge_points` 逐字复制本次所选标签原文，并要求用户消息以 JSON 数组形式重申这些标签，不得改写为资料正文的细分说法（如资料写「共面向量定理」而所选标签为「空间向量」）。此约束只在提示词侧生效，校验器 MUST NOT 依据语义猜测或同义词表补全归属。

解析前，服务端 MUST 只在 JSON 字符串字面量内部修补 LaTeX 反斜杠：反斜杠后不是合法 JSON 转义字符时补成两个；`\b`、`\f`、`\t`、`\r` 后紧跟 ASCII 字母时视为 LaTeX 命令补成两个；`\n` 仅在其后字母串属于设计列出的 LaTeX 命令白名单时补成两个，否则保留为换行。已合法的 `\\`、`\"`、`\/`、`\uXXXX` 及字符串外的内容 MUST NOT 改动。修补次数 MUST 记入本次 `generate` 事件详情。修补后整体仍不是合法 JSON，或缺少 `questions` / `gaps` 数组时，本次生成失败，不保存任何题目，失败原因 MUST 带解析出错的行列位置，MUST NOT 保存模型原文。修补只恢复字符，MUST NOT 宣称证明公式或题目正确。

服务端 MUST 对每道题独立校验，全部规则如下：

- 字段集合恰为 `type`、`difficulty`、`knowledge_points`、`stem`、`options`、`answer`、`explanation`、`origin`、`source_refs`。
- `type` 与 `difficulty` 取规定枚举值。
- `knowledge_points` 为本次所选知识点的非空子集。字面上包含该标签的表述（如所选「空间向量」而模型写「空间向量基本定理」）MUST 向上归一到该标签（可被多个标签包含时取最长者）再去重；归一后仍不在子集内才算越界。不构成字面包含的细分说法（如「共面向量定理」）MUST 判为越界，由提示词侧约束避免，不在校验器内做同义词或语义推断。
- `origin` 取 `original`（原题）、`adapted`（改编）或 `new`（依据资料新编）。
- `source_refs` 至少一个，且都是本次提供的 S 编号。
- 长度上限：`stem` 与 `explanation` 非空，各不超过 3000 字；每个选项不超过 500 字。
- 单选和多选：`options` 恰为 A–D 四个标签互不重复、文本非空的选项。单选的 `answer` 为其中一个标签；多选的 `answer` 为 2–4 个互不重复的标签。
- 判断：`options` 为空数组，`answer` 为布尔值。
- 填空：`options` 为空数组；题干中连续 4 个及以上下划线的空位数为 1–5，且等于 `answer` 字符串数组的长度，数组每项非空。
- 解答：`options` 为空数组，`answer` 为非空字符串（参考答案或评分要点）。
- 内容限制：题干与选项不得含「答案 / 解析 / 解答 / 教师提示」等显式标记，也不得含 S 引用编号。题干、选项、答案、解析中的配图只能是所选资料原图的给定路径。全部字段不得含 HTML、外部链接或私有接口地址。
- 控制字符：题干、选项文本、答案、解析不得含退格（U+0008）或换页（U+000C），否则判为未通过，原因为「含不可见控制字符，疑似公式转义错误」。修改与通过复核时同样适用。
- 配额：按题目在数组中的顺序计数，某题会使其题型或难度超出请求数量时，判为「超出配比」。

通过的题目 MUST 以「待复核」状态落库；未通过的题目 MUST NOT 落库，`done` 帧 MUST 返回其序号与全部未通过原因。`gaps` 每项含题型、难度、知识点、原因，页面 MUST 显示为「待补充」。通过题数少于请求时，页面 MUST 显示缺口；MUST NOT 自动重试凑数，也不得把缺口显示为已完成。

#### Scenario: 全部题目通过校验

- **WHEN** 模型返回 8 道格式合法、配额吻合、引用有效的题目且 `gaps` 为空
- **THEN** 8 道题以待复核状态保存，`done` 帧列出 8 个题目编号，0 个未通过

#### Scenario: 部分题目不合格

- **WHEN** 模型返回的 8 道题中，一道单选答案为「E」，一道引用了未提供的 [S9]
- **THEN** 6 道题保存为待复核，`done` 帧列出 2 道未通过题的序号与原因，页面显示缺 2 题

#### Scenario: 模型返回字面包含所选标签的表述

- **WHEN** 本次所选知识点为「空间向量」，模型返回的题目 `knowledge_points` 为 `["空间向量基本定理"]`
- **THEN** 服务端将该题知识点归一并保存为「空间向量」，该题通过校验

#### Scenario: 模型返回不构成字面包含的细分说法

- **WHEN** 本次所选知识点为「空间向量」，模型返回的题目 `knowledge_points` 为 `["共面向量定理"]`（资料原文的细分术语，不含所选标签字面）
- **THEN** 该题未通过校验，原因为知识点超出本次所选范围；提示词已要求逐字复制标签，此情形属于模型未遵守约束，不得由校验器推断归属

#### Scenario: 细分知识点与所选知识点无关

- **WHEN** 本次所选知识点为「空间向量」，某题 `knowledge_points` 为 `["数列求和"]`
- **THEN** 该题未通过校验，原因为知识点超出本次所选范围

#### Scenario: 模型声明无依据的空位

- **WHEN** 模型对一道「难 · 解答题」返回 `gaps` 项，说明资料中没有足够依据
- **THEN** 该空位显示为「待补充」，不生成占位题，也不计入已生成数量

#### Scenario: 输出不是 JSON

- **WHEN** 模型返回 Markdown 正文而非 JSON 对象
- **THEN** 通过 SSE `error` 帧提示格式错误，不保存任何题目，生成记录标记为失败

#### Scenario: 单反斜杠 LaTeX 被修补后通过

- **WHEN** 模型返回的 JSON 在同一题干中混用 `\\overrightarrow{AB}` 与 `\overrightarrow{AF}`、`\vec{a}`，其余格式合法
- **THEN** 解析成功，题干中三处都还原为 LaTeX 命令 `\overrightarrow`、`\vec`，题目按其余规则校验后保存为待复核，`generate` 事件记录的修补次数为 2

#### Scenario: 被误解码的公式命令被修补

- **WHEN** 模型返回的解析含单反斜杠 `\frac{1}{2}`、`\times`、`\neq`，且同一字段有一处换行写作 `\n第二步`
- **THEN** 三个命令都还原为 LaTeX，`\n第二步` 仍是换行加正文，字段中不含换页、制表等控制字符

#### Scenario: 修补后仍不是合法 JSON

- **WHEN** 模型输出在第 12 行中途被截断
- **THEN** 本次生成失败，不保存任何题目，生成记录的失败原因含「第 12 行」及列号，不含模型原文

#### Scenario: 漏网的控制字符被拦截

- **WHEN** 某题题干在解析后含换页符（U+000C）
- **THEN** 该题未通过校验，原因为「含不可见控制字符，疑似公式转义错误」，其余合格题目照常保存

#### Scenario: 题干泄露答案

- **WHEN** 某题题干中出现「答案：B」
- **THEN** 该题未通过校验，原因为题干含答案标记
