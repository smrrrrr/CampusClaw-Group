## Why

小组选题把「智能命题」列为第一阶段主路径（智能备课 + 智能命题 + 学情诊断形成闭环）的第二块：按考查知识点、题型与难度分布生成试题，附答案、解析与出处；教师逐题复核（通过 / 修改 / 驳回），通过的题目沉淀进学科题库；按配比组卷并发布给本班。验收要点是三条硬约束：模型输出须为结构化题目且校验通过才入库；未经人工复核的题目不能进入题库；出处可回溯到讲义。

当前系统里，教研中心的「智能命题」仍是占位入口（teacher-workspace 规约「全科总览与单科教学入口区分」明确要求占位），没有题目、题库或试卷实体。但命题所需的底座已经具备：学科组教师资料（research-materials，带答案的教师版、按学科共享、SHA 指纹）、备课已用过的「完整小节 + S 编号 + 原文行号」来源组织方式（smart-lesson-prep）、DeepSeek 流式调用与 SSE 帧、学生版去答案校验、以及「班级资料 Material + 配图复制」的分班发布链路。本变更在这些已有能力上补齐命题闭环，并为后续「学情诊断」留下按题目与知识点归档的数据接口。

## What Changes

- **新增命题生成（教师）**：教师在新页面 `/teacher/quiz` 选择 1–5 份本学科教研组资料、1–5 个考查知识点（取自后端学科知识点词表），给出各题型数量与易/中/难数量（单次合计 1–20 题），选填补充要求。后端从数据库读取教师学科，复用备课的完整小节提取与 S 编号，要求模型只输出一个 JSON 对象（`questions` + `gaps`）。生成以 SSE `progress` 帧推送进度，`done` 帧给出通过、未通过及「待补充」缺口；未配 Key 返回 503；同一教师同时只允许一个命题任务。
- **结构化输出与逐题校验**：服务端按题型规则逐题校验（单选 / 多选 / 判断 / 填空 / 解答五种题型的选项、答案与空位格式，难度与题型配额，知识点属于本次所选，至少一个有效 S 引用，题干与选项不得含答案标记，配图只能是所选资料原图，无 HTML / 外部链接）。通过的题目才以「待复核」状态落库，未通过的只返回原因不落库；模型无法给出依据的空位必须列为 `gaps` 并在界面显示为「待补充」，不得编造凑数。
- **出处快照**：每道题保存所引用片段的资料编号、文件名、原文行号、完整摘录与文件 SHA-256，教师可逐题查看原文并跳转教研组原稿；与备课一致，编号和指纹只证明来源身份，语义是否支持仍由教师复核。
- **逐题人工复核**：候选题仅作者可见。作者逐题执行「通过」（须显式确认已核对题干、答案、解析与出处）、「修改后保存」（重新走同一套校验，仍为待复核）或「驳回」（可填原因）。不提供批量通过接口。只有「通过」才进入题库，同一学科题干规范化后重复的题目拒绝入库并指出已有题号。
- **学科题库**：已通过题目对本学科全部教师可见（含答案与解析），可按知识点、题型、难度、关键字、作者筛选。入库题目内容不可原地修改：需要改动时「复制为新候选」，重新复核后作为新题入库；作者可「下架」题目，下架题不再参与组卷，已有试卷快照不受影响。
- **按配比组卷**：教师给出试卷标题、时长、知识点范围、各题型题数与每题分值、易/中/难百分比，后端用写入规约的确定性算法（最大余数法分配难度 → 按「被用次数少、题号小」选题）从题库抽题，题量不足返回 422 并列出每个「题型 × 难度」的缺口，不调用模型补题。教师可替换、增删、排序、改分值，定稿后只读。
- **分班发布与答案卷**：定稿试卷由服务端从题目快照渲染学生卷（无答案、解析与出处），教师确认核对后选择任教班级发布；任一班级越权整批 403。每班生成独立的班级资料（标签含学科、知识点、「试卷」），复制实际使用的原图并校验指纹；试卷不进入学生助手检索索引。相同试卷内容重复发布复用原记录。教师可下载仅本人可见的答案卷（答案、解析、出处）。
- **范围隔离**：题库按学科组（沿用现有 `User.subject` 即学科组的口径）隔离；候选题、试卷、生成记录仅作者可访问。跨学科或他人资源按编号访问一律返回与不存在一致的 404；学生访问命题接口 403。
- **命题审计**：生成、修改、通过、驳回、复制、下架、删除、组卷、定稿、发布都写入命题事件记录（谁、何时、对哪道题 / 哪份卷、做了什么、内容指纹前后），题目详情可查看其复核历史。
- **工作区与文档**：教研中心「智能命题」从占位改为真实入口（旧 `view=lesson-quiz` 重定向到 `/teacher/quiz`）；教研问答、课例分析仍为占位。新接口补充 OpenAPI 注解；`apitest/` 增加以虚构模型驱动的命题检查脚本。

## Capabilities

### New Capabilities

- `smart-question-generation`: 命题生成请求与知识点词表、来源片段与出处快照、结构化输出与逐题校验、流式进度与失败处理、候选题逐题复核、学科题库、按配比组卷、试卷定稿与分班发布、范围隔离、命题审计、接口文档与验收脚本。

### Modified Capabilities

- `teacher-workspace`: 「教师共用工作空间导航」把 `/teacher/quiz` 纳入共用导航；「全科总览与单科教学入口区分」中智能命题由占位改为真实入口，教研问答与课例分析保持占位。

## Impact

- 后端：新增 `question_generations`、`question_items`、`question_papers`、`question_paper_items`、`quiz_publications`、`question_events` 六张表（启动 `create_all` 建表，不改旧表结构）；新增 `question_service.py`（提示词、解析与校验、组卷算法、学生卷渲染）与 `routers/quiz.py`（`/api/teacher/quiz/*`）；复用 `lesson_service.build_resources/context_text/validate_links`、`research_service.validate_student_text`、`llm_service.stream_chat`、`material_service.write_physical_file`，`knowledge_tags.TOPICS` 作为知识点词表的唯一来源。
- 前端：新增 `/teacher/quiz`（生成命题、待复核、学科题库、组卷与发布四个标签页）；教师侧栏与 `view=lesson-quiz` 重定向；学生端无新页面，试卷出现在现有班级资料列表中。
- 部署：无新服务、无新环境变量；继续使用已配置的 `DEEPSEEK_API_KEY`（未配置时生成返回 503，题库、组卷、发布不受影响）。
- 数据交接：新表含教师题目、答案与发布记录，属于组内私有数据，随数据库一起交接；交接包仍不含 `.env`。
- 不改变：智能备课、教研组资料、学生助手、MCP 工具、检索索引与班级 / 学科隔离的现有行为；现有教研资料接口的跨学科 403 口径不在本次修改。
- 与选题说明的差异：选题说明的技术方案写的是 Go + MySQL + Qdrant + Vite，但当前仓库实际为 FastAPI + SQLite + Next.js（个人项目延续而来）。本变更按仓库现状实现，不迁移技术栈；如小组决定迁移，应作为独立 change 提出。
