## 实际执行

### 构建与离线检查

| 环节 | 命令/方式 | 结果 | 来源 |
| --- | --- | --- | --- |
| 前端构建 | `npm run build`，随后重建前端容器 | 通过，两轮各一次 | 前端修复会话报告；浏览器里看到的行为与新代码一致，说明容器已更新 |
| 规约校验 | `openspec validate fix-quiz-markdown-rendering --strict` | valid | 验收会话复跑 |
| 空位转换离线用例 | 把 `protectFillBlanks` 的正则复制到 node 脚本（放会话临时目录，未入仓库），共 8 例 | **8/8 通过** | 验收会话 |

8 个离线用例的输入：

- 三个连续空位 `____，____，____。`
- 公式下标 `$A_1B_1$` 与空位同时出现
- 行内代码和围栏代码里的 `____`
- 整行下划线
- 已有反斜杠的 `\____`
- `__粗体__`
- 正文里出现两个 `$` 金额
- `$$` 块公式内部的 `x_1____`

结果都符合 design §3：

- 只有正文中的空位被转义。
- 代码、公式、整行下划线、已转义的下划线和双下划线粗体保持原样。

前端修复会话另用 react-markdown + remark-math + rehype-katex 跑过 design 中的用例（tasks 3.1），结果见该会话。

## 未覆盖 / 未完成项

1. **构建没有复跑**：`npm run build` 与 tasks 3.1 的渲染脚本由前端修复会话执行，验收会话没有复跑，只从浏览器行为确认容器里是新代码。
2. **打印 / 另存 PDF**：没有实际打印，按 proposal 的说法，打印用的是同一渲染结果。
3. **学生 AI 回答**：没有专门构造含 4 个以上连续下划线的回答，只由离线用例覆盖。
4. **多空位题与公式下标同题**：浏览器里 #8 同时含 `$ABCD-A_1B_1C_1D_1$` 与空位，渲染正常；但「下标紧挨空位」这种更极端的写法只由离线用例覆盖。
5. **块级公式选项**：spec 允许含块级公式的选项不同行，现有题目没有这种选项，未验证。

## 观察（不属于本变更）

- **测试账号密码**：`apitest/conftest.py` 与 `DEPLOYMENT.md` 写的学生密码是种子初始密码，与交接数据副本不一致；交接副本的演示密码见交接说明。在这套数据上用默认值登录会失败，需要用环境变量 `APITEST_STUDENT_PASSWORD` 覆盖。这次因此多了 1 条 `login_attempts` 失败记录。
- **组卷难度比例按整卷计算**：题库题量少的时候，不同难度的题型无法组进同一份试卷，会提示缺口。这是既有设计，不是本变更引入的。

## 结论

规约中《题目内容显示》的全部 9 个 Scenario 都已验证通过，其中 8 个在浏览器里验证，「代码中的下划线」由离线用例验证：

- 选择题、判断题的答案和编辑框保持原样。
- 解答题作答横线不变。
- 同一渲染器上的备课预览没有回归。
