## Context

- **逐题校验入口**：`backend/question_service.py` 的 `validate_question(q, ctx)`。它被三处调用：生成时的 `validate_batch`、修改保存（`routers/quiz.py` 的 `PUT /items/{id}`）、通过（`POST /items/{id}/approve`）。修改和通过在有原因时返回 400，原因用「；」连接。
- **现有内容检查**：答案标记、S 编号、控制字符（`has_control_chars`）、链接与配图（`validate_links`）。没有任何公式结构检查。
- **学生卷**：`render_student_paper(paper, items)` 从题目快照生成 Markdown。
  - 选择题现在输出 `f"{number}. {stem}"`，下一行是 `f"   {opts}"`，其中四个选项用全角空格连接。
  - 解答题在空行后输出 4 行下划线作答横线（独占一行，渲染为分隔线），这次不改。
- **学生卷用在哪**：教师端预览（`/teacher/quiz` 的学生卷预览）和发布后的班级资料（学生在本班资料里打开），都由前端 `MarkdownAnswer` 渲染（react-markdown 9.0.1 + remark-math 6.0.0 + rehype-katex 7.0.1）。

## Goals / Non-Goals

**Goals**

- 公式里缺 `}` 或 `$` 不成对的题目，在生成、修改和通过时都会被拦下，原因写明是哪个字段。
- 学生卷中，选择题的每个选项各占一行；50 题以内题号连续，选项不会脱离所在题目。

**Non-Goals**

- 不做完整的 LaTeX 语法检查：不检查 `\left` / `\right`、`\begin` / `\end` 是否配对，不检查命令拼写，后端也不调用 KaTeX。
- 不自动修补括号。缺的括号该补在哪个位置并不确定，由教师修改或重新生成。
- 不重新校验已通过入库的题目，不改写已发布的班级资料。
- 不改答案卷（它目前不输出选项，这次也不改）、教师端题目详情和前端渲染器。

## Decisions

### 1. 公式结构检查（`check_formula_structure(text) -> list[str]`）

每个字段单独检查：题干、选项 A–D 的文本、答案里的字符串（填空的每一项、解答题的答案）、解析。判断题的布尔答案和选择题的选项字母不检查。

步骤：

1. 先把转义的 `\$` 当作普通字符去掉。
2. 切分公式：用一个正则交替匹配 `$$…$$` 与 `$…$`（跨行，非贪婪；块级写在前面，优先匹配）。切分方式和前端 `normalizeLatex` 一致。
3. 匹配完后，剩下的文本里还有 `$`，就记为「公式定界符 $ 不成对」。
4. 在每段公式内从左到右扫描：
   - 遇到 `\` 时，连同它后面的一个字符一起跳过，因此 `\{`、`\}`、`\\` 都不计数；
   - `{` 计 +1，`}` 计 −1；
   - 中途计数小于 0，或扫描结束时不等于 0，记为「公式花括号不配对」。
5. 一个字段最多报一条花括号原因、一条定界符原因。原因前面加字段名：`题干`、`选项 A`…`选项 D`、`答案`、`解析`，例如「选项 D 公式花括号不配对」。

放在 `validate_question` 的内容检查之后，与控制字符检查同级。任一原因出现，该题都不通过：生成时不落库，修改或通过时返回 400。

不检查公式外的花括号：中文正文里的 `{` 本来就是普通字符，渲染器不会报错。

离线用例：

| 输入 | 期望 |
| --- | --- |
| `$-\frac{1}{2}\vec{c$`（#15 原样） | 花括号不配对 |
| `$\vec{a}$`、`$$\begin{cases}x\\y\end{cases}$$` | 通过 |
| `$\{x\mid x>0\}$`、`$\left\{ a \right.$` | 通过（转义括号不计） |
| `$a}{b$` | 不配对（中途计数为负） |
| `$\frac{1}{2}` | 定界符不成对 |
| `价格 \$5，$x$` | 通过 |
| `解析中 $$x$$ 与 $y$ 混用` | 通过 |
| 公式外 `集合{1,2}` | 通过（公式外不检查） |

### 2. 不配对时：拒绝入库，而不是带警告入库

选择与控制字符、答案标记等现有规则一致：判为未通过。2026-10-25 评审确认采用本方案，不采用下面的备选。

- **理由**：现行规约要求未通过的题目不落库；通过时也会重新执行完整校验。如果只是带警告入库，教师不改就点不了通过，等于多了一种「入库但卡住」的状态，界面和规约都要另加说明。
- **代价**：这道题直接丢掉，页面显示缺口。教师要重新生成，或在补充要求里提示完整书写公式。提示词新增的规则（Decision 3）用来降低出现概率。
- **备选**：带警告保存为待复核，详情面板标出不配对的字段，教师修改后才能通过。好处是一次修改就能救回整题。如果评审认为丢题代价太大，可以改用这个方案，但要同时修改《结构化输出与逐题校验》中「未通过的题目 MUST NOT 落库」的口径。

### 3. 提示词

在 `QUESTION_PROMPT` 的第 6 条（公式与反斜杠）后面追加一句：

> 公式中的花括号必须成对；资料里 `\vec a`、`\frac12` 这类省略括号的写法，改写时写成完整的 `\vec{a}`、`\frac{1}{2}`，不要漏掉右括号。

提示词只用来降低出错概率，最终以校验为准。

### 4. 学生卷选项排版

设 `indent = " " * len(f"{number}. ")`：题号 1–9 缩进 3 格，10–50 缩进 4 格。

- **题干**：第一行接在 `n. ` 后面；题干如果有多行，续行都加 `indent` 前缀，空行保持为空行。现有数据里没有多行题干，这一条是预防。
- **选择题选项**：题干之后输出一个空行，然后每个选项输出一行 `indent + "A. " + 文本`，除最后一项外，行尾加 `\`（CommonMark 硬换行）。四个选项在列表项内单独成段，项与项之间用 `<br>` 分隔。
- **选项含换行时**：任一选项文本含 `\n` 时，不用硬换行，改为每个选项单独成段（选项之间空一行，续行同样加 `indent`）。原因是硬换行的 `\` 如果写在 `$$` 闭合行后面，会让块级公式无法闭合。
- **其他题型**：判断、填空题不变。解答题作答横线保持现有输出，横线渲染为分隔线后，下一题由 `<ol start>` 接续编号，这是现状，不改。

离线用例（用前端已安装的 react-markdown + remark-math + rehype-katex 实际渲染；第 1–3 行已在提案阶段验证）：

| 输入 | 期望 |
| --- | --- |
| 第 1 题，四个单行选项 | 题干一个 `<p>`，选项一个 `<p>`，中间 3 个 `<br>` |
| 第 10 题，缩进 4 格 | 同上，`<ol start="10">`，第 11 题在同一个列表里 |
| 第 10 题仍缩进 3 格（反例，仅作对照） | 选项脱离列表，题号断开 |
| 选项含 `$\vec{a}$` 等行内公式 | 公式渲染，`.katex-error` 为 0 |
| 某选项含 `$$…$$` 两行 | 每个选项单独成段，块级公式正常 |
| 多行题干（含空行与 `$$` 块） | 续行都在同一列表项内 |
| 多选与单选混排，再接填空、解答 | 分节标题与编号连续，解答题横线不变 |

### 5. 学生卷指纹与重复发布

学生卷正文变了，指纹也随之变化。按现行规约，同一试卷、同一班级、同一指纹才复用已有资料，所以变更后再发布含选择题的试卷，会生成新的班级资料。已有资料不改写，也不自动下架。这是有意为之：旧资料保持发布时的原样，可追溯。

## Risks / Trade-offs

- **误判**：
  - 公式里写字面的花括号要用 `\{`、`\}`，这是 LaTeX 的标准写法，不会被误判；
  - 写成 `\lbrace` 这类命令的也不涉及 `{`。
  - 唯一可能误判的是作者故意写了不配对的花括号，但这样的公式 KaTeX 本身也渲染不出来。
- **`$` 用作货币符号**：数学、物理题干很少出现。没转义的 `$` 会被判定界符不成对，教师修改时写成 `\$` 即可。
- **丢题**：见 Decision 2 的取舍与备选。
- **硬换行**：行尾 `\` 已在当前前端依赖版本离线验证。将来升级 react-markdown 或 remark-math 时，要重跑 §4 用例。

## 已知限制

- 只检查 `$` 和花括号，不检查其他 LaTeX 结构。KaTeX 能报错的其他情况，仍要靠教师复核时看页面。
- 前端没有单元测试框架。排版用离线脚本加浏览器检查来验证，公式检查由 `check_question_bank.py` 覆盖。
