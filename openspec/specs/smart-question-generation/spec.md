# smart-question-generation Specification

## Purpose
2026-10-25 归档：实现“选择本学科教研组资料与知识点 → 按题型和难度生成结构化试题（附答案、解析与出处）→ 逐题校验后作为待复核候选题保存 → 教师逐题通过、修改或驳回 → 通过的题目进入学科题库 → 按配比组卷、定稿并发布到本班”。未经人工复核的题目不能进入题库；出处快照只证明来源身份，语义是否支持仍由教师复核。

## Requirements

### Requirement: 发起命题生成

教师 MUST 在 `/teacher/quiz` 发起命题：选择 1–5 份本学科 ResearchMaterial，1–5 个考查知识点，各题型题数（单选 `single_choice`、多选 `multiple_choice`、判断 `true_false`、填空 `fill_blank`、解答 `short_answer`，每种 0–10），易 / 中 / 难题数（`easy` / `medium` / `hard`），选填不超过 2000 字的补充要求。题型题数之和 MUST 等于难度题数之和，且为 1–20，否则返回 400。

后端 MUST 使用当前数据库中的教师学科，不接受客户端指定学科；未分配学科或学科不在 `SUBJECT_NAMES` 中的教师返回 403。所选资料中任何一份不属于本学科或不存在，MUST 按不存在返回 404。

知识点 MUST 取自后端学科知识点词表（`knowledge_tags.TOPICS[学科]`，唯一来源），词表外的知识点返回 400。`GET /api/teacher/quiz/knowledge-points` MUST 返回本学科词表供页面选择。

本期没有真实学情接入。命题 MUST NOT 读取或虚构班级统计、薄弱点。页面 MUST 说明点击生成会把所选资料片段和命题要求发送给已配置的 DeepSeek，配图只发送路径、不发送图片本体。

#### Scenario: 数学教师按配比发起命题

- **WHEN** 数学教师选择两份数学组资料、知识点「立体几何」，要求单选 4 题、填空 2 题、解答 2 题，易 3、中 3、难 2
- **THEN** 后端接受请求，以数学学科组织上下文；不使用其他学科资料或学生班级资料

#### Scenario: 配比不一致或越界

- **WHEN** 题型合计为 8 而难度合计为 7，或总题数为 0 或 21，或某题型数为 11
- **THEN** 返回 400，说明具体不合法的字段，不调用模型

#### Scenario: 选用他科资料

- **WHEN** 数学教师在请求中放入一份物理组资料的编号
- **THEN** 返回 404，与资料不存在的响应一致，不调用模型

#### Scenario: 使用词表外的知识点

- **WHEN** 请求的知识点不在本学科知识点词表中
- **THEN** 返回 400，提示从词表中选择

### Requirement: 来源片段与出处快照

命题上下文 MUST 复用智能备课的完整小节提取：按知识点与补充要求排序，最多 16 个片段、合计不超过 45000 字符；每份所选资料至少提供一个完整小节。超出预算或缺少合适小节 MUST 提示调整，不得截断题目或公式。每个片段 MUST 带有本次生成内唯一的 S 编号。

每道落库题目 MUST 保存其引用片段的快照：S 编号、资料编号、文件名、原文起止行号、完整摘录、文件 SHA-256。之后资料被修改或删除，快照 MUST 保留不变；界面 MUST 标明原稿已变化或已删除，而不是隐藏出处。

编号和指纹只证明来源身份，MUST NOT 宣称自动证明题目、答案或解析在语义上被原文支持；正确性由教师复核。

#### Scenario: 查看题目出处

- **WHEN** 教师打开一道引用 [S2] 的候选题
- **THEN** 页面显示 S2 的资料名、原文行号、完整摘录与文件指纹，并可打开对应教研组原稿

#### Scenario: 原稿在入库后被替换

- **WHEN** 题目入库后，其引用的教研资料被重新导入为不同内容
- **THEN** 题目详情仍显示入库时的摘录与原指纹，并标注「原稿已变化」

### Requirement: 结构化输出与逐题校验

模型 MUST 被要求只输出一个 JSON 对象：`questions` 为题目数组，`gaps` 为无法给出依据的空位数组，并被提示 JSON 字符串里每个 LaTeX 反斜杠都写成两个。外层若包有单个代码围栏，MUST 先剥除再解析。

提示词 MUST 要求 `knowledge_points` 逐字复制本次所选标签原文，并要求用户消息以 JSON 数组形式重申这些标签，不得改写为资料正文的细分说法（如资料写「共面向量定理」而所选标签为「空间向量」）。此约束只在提示词侧生效，校验器 MUST NOT 依据语义猜测或同义词表补全归属。

解析前，服务端 MUST 只在 JSON 字符串字面量内部修补 LaTeX 反斜杠：反斜杠后不是合法 JSON 转义字符时补成两个；`\b`、`\f`、`\t`、`\r` 后紧跟 ASCII 字母时视为 LaTeX 命令补成两个；`\n` 仅在其后字母串属于设计列出的 LaTeX 命令白名单时补成两个，否则保留为换行。已合法的 `\\`、`\"`、`\/`、`\uXXXX` 及字符串外的内容 MUST NOT 改动。修补次数 MUST 记入本次 `generate` 事件详情。修补后整体仍不是合法 JSON，或缺少 `questions` / `gaps` 数组时，本次生成失败，不保存任何题目，失败原因 MUST 带解析出错的行列位置，MUST NOT 保存模型原文。修补只恢复字符，MUST NOT 宣称证明公式或题目正确。

服务端 MUST 对每道题独立校验，全部规则如下：

- 字段集合恰为 `type`、`difficulty`、`knowledge_points`、`stem`、`options`、`answer`、`explanation`、`origin`、`source_refs`。
- `type` 与 `difficulty` 取规定枚举值。
- `knowledge_points` 为本次所选知识点的非空子集。字面上包含该标签的表述（如所选「空间向量」而模型写「空间向量基本定理」）MUST 向上归一到该标签（可被多个标签包含时取最长者）再去重；归一后仍不在子集内才算越界。不构成字面包含的细分说法（如「共面向量定理」）MUST 判为越界，由提示词侧约束避免，不在校验器内做同义词或语义推断。
- `origin` 取 `original`（原题）、`adapted`（改编）或 `new`（依据资料新编）。
- `source_refs` 至少一个，且都是本次提供的 S 编号。
- 长度上限：`stem` 与 `explanation` 非空，各不超过 3000 字；每个选项不超过 500 字。
- 单选和多选：`options` 恰为 A–D 四个标签互不重复、文本非空的选项。单选的 `answer` 为其中一个标签；多选的 `answer` 为 2–4 个互不重复的标签。
- 判断：`options` 为空数组，`answer` 为布尔值。
- 填空：`options` 为空数组；题干中连续 4 个及以上下划线的空位数为 1–5，且等于 `answer` 字符串数组的长度，数组每项非空。
- 解答：`options` 为空数组，`answer` 为非空字符串（参考答案或评分要点）。
- 内容限制：题干与选项不得含「答案 / 解析 / 解答 / 教师提示」等显式标记，也不得含 S 引用编号。题干、选项、答案、解析中的配图只能是所选资料原图的给定路径。全部字段不得含 HTML、外部链接或私有接口地址。
- 控制字符：题干、选项文本、答案、解析不得含退格（U+0008）或换页（U+000C），否则判为未通过，原因为「含不可见控制字符，疑似公式转义错误」。修改与通过复核时同样适用。
- 配额：按题目在数组中的顺序计数，某题会使其题型或难度超出请求数量时，判为「超出配比」。

通过的题目 MUST 以「待复核」状态落库；未通过的题目 MUST NOT 落库，`done` 帧 MUST 返回其序号与全部未通过原因。`gaps` 每项含题型、难度、知识点、原因，页面 MUST 显示为「待补充」。通过题数少于请求时，页面 MUST 显示缺口；MUST NOT 自动重试凑数，也不得把缺口显示为已完成。

#### Scenario: 全部题目通过校验

- **WHEN** 模型返回 8 道格式合法、配额吻合、引用有效的题目且 `gaps` 为空
- **THEN** 8 道题以待复核状态保存，`done` 帧列出 8 个题目编号，0 个未通过

#### Scenario: 部分题目不合格

- **WHEN** 模型返回的 8 道题中，一道单选答案为「E」，一道引用了未提供的 [S9]
- **THEN** 6 道题保存为待复核，`done` 帧列出 2 道未通过题的序号与原因，页面显示缺 2 题

#### Scenario: 模型返回字面包含所选标签的表述

- **WHEN** 本次所选知识点为「空间向量」，模型返回的题目 `knowledge_points` 为 `["空间向量基本定理"]`
- **THEN** 服务端将该题知识点归一并保存为「空间向量」，该题通过校验

#### Scenario: 模型返回不构成字面包含的细分说法

- **WHEN** 本次所选知识点为「空间向量」，模型返回的题目 `knowledge_points` 为 `["共面向量定理"]`（资料原文的细分术语，不含所选标签字面）
- **THEN** 该题未通过校验，原因为知识点超出本次所选范围；提示词已要求逐字复制标签，此情形属于模型未遵守约束，不得由校验器推断归属

#### Scenario: 细分知识点与所选知识点无关

- **WHEN** 本次所选知识点为「空间向量」，某题 `knowledge_points` 为 `["数列求和"]`
- **THEN** 该题未通过校验，原因为知识点超出本次所选范围

#### Scenario: 模型声明无依据的空位

- **WHEN** 模型对一道「难 · 解答题」返回 `gaps` 项，说明资料中没有足够依据
- **THEN** 该空位显示为「待补充」，不生成占位题，也不计入已生成数量

#### Scenario: 输出不是 JSON

- **WHEN** 模型返回 Markdown 正文而非 JSON 对象
- **THEN** 通过 SSE `error` 帧提示格式错误，不保存任何题目，生成记录标记为失败

#### Scenario: 单反斜杠 LaTeX 被修补后通过

- **WHEN** 模型返回的 JSON 在同一题干中混用 `\\overrightarrow{AB}` 与 `\overrightarrow{AF}`、`\vec{a}`，其余格式合法
- **THEN** 解析成功，题干中三处都还原为 LaTeX 命令 `\overrightarrow`、`\vec`，题目按其余规则校验后保存为待复核，`generate` 事件记录的修补次数为 2

#### Scenario: 被误解码的公式命令被修补

- **WHEN** 模型返回的解析含单反斜杠 `\frac{1}{2}`、`\times`、`\neq`，且同一字段有一处换行写作 `\n第二步`
- **THEN** 三个命令都还原为 LaTeX，`\n第二步` 仍是换行加正文，字段中不含换页、制表等控制字符

#### Scenario: 修补后仍不是合法 JSON

- **WHEN** 模型输出在第 12 行中途被截断
- **THEN** 本次生成失败，不保存任何题目，生成记录的失败原因含「第 12 行」及列号，不含模型原文

#### Scenario: 漏网的控制字符被拦截

- **WHEN** 某题题干在解析后含换页符（U+000C）
- **THEN** 该题未通过校验，原因为「含不可见控制字符，疑似公式转义错误」，其余合格题目照常保存

#### Scenario: 题干泄露答案

- **WHEN** 某题题干中出现「答案：B」
- **THEN** 该题未通过校验，原因为题干含答案标记

### Requirement: 流式进度与失败处理

`POST /api/teacher/quiz/generations` MUST 复用现有 `stream_chat`，总时限 180 秒，以 SSE 返回：`progress` 帧（已收到的字符数）、`done` 帧（生成记录编号、通过题目编号、未通过明细、gaps）或 `error` 帧（可读原因）。只有服务端完成解析与校验后才发送 `done`；前端没有收到 `done` MUST 按中断处理。

未配置 DeepSeek Key 时 MUST 在开始流之前返回 503。同一教师同时只允许一个命题任务，第二个请求返回 409；任务完成、失败或断开后 MUST 释放。失败、超时或中断时 MUST NOT 保存题目，表单输入保留，不伪装为离线生成结果。

#### Scenario: 生成中模型超时

- **WHEN** 模型在 180 秒内未完成输出
- **THEN** 前端收到 `error` 帧，不保存任何题目，教师可直接重试

#### Scenario: 同一教师重复点击生成

- **WHEN** 第一个命题任务尚未结束时，同一教师再次提交
- **THEN** 第二个请求返回 409，第一个任务不受影响

#### Scenario: 未配置模型 Key

- **WHEN** 服务端没有配置 DeepSeek Key 时教师发起命题
- **THEN** 返回 503，题库浏览、组卷与发布功能照常可用

### Requirement: 候选题逐题复核

候选题（`pending`、`rejected`）MUST 仅作者可见。作者 MUST 逐题复核，每个写操作携带 `revision` 并执行乐观锁，落后的 `revision` 返回 409。可执行的操作：

- **修改并保存**（`PUT /items/{id}`）：仅 `pending` 可修改，重新执行结构化校验（知识点范围为本学科词表，出处只能保留或删减原快照中的 S 编号，至少保留一个），状态保持 `pending`。
- **通过**（`POST /items/{id}/approve`）：仅 `pending` 可通过，请求 MUST 带 `confirmed=true` 表示已核对题干、答案、解析与出处，否则返回 400。通过前 MUST 再次执行完整校验。同学科已有未下架题目的规范化题干（去空白、全半角统一）与之相同时，返回 409 并给出已有题号。成功后状态为 `approved`，记录复核人、时间以及题目在复核中是否被修改过。
- **驳回**（`POST /items/{id}/reject`）：仅 `pending` 可驳回，可填写不超过 500 字的原因。驳回的题目不可再通过，只可删除。

系统 MUST NOT 提供批量通过接口，也不得在生成、修改或任何其他操作中把题目置为 `approved`。

#### Scenario: 修改后通过

- **WHEN** 作者把一道候选单选题的选项 C 改正后保存，再勾选确认并通过
- **THEN** 保存后仍为待复核，通过后进入题库，复核记录标明「已修改」

#### Scenario: 未确认即通过

- **WHEN** 作者调用通过接口但 `confirmed` 为 false 或缺失
- **THEN** 返回 400，题目仍为待复核，不进入题库

#### Scenario: 重复题目

- **WHEN** 候选题题干与本学科题库中一道未下架题目在规范化后相同
- **THEN** 通过请求返回 409，并给出已有题号，候选题保持待复核

#### Scenario: 驳回后尝试通过

- **WHEN** 作者对已驳回的题目调用通过接口
- **THEN** 返回 409，题目不进入题库

### Requirement: 学科题库

`approved` 题目 MUST 构成本学科题库，本学科所有教师可浏览题干、选项、答案、解析、出处快照与复核历史。浏览支持按知识点、题型、难度、关键字、作者、是否下架筛选，每页最多 50 条。

入库题目的内容 MUST NOT 被原地修改。需要改动时，任一本学科教师可「复制为新候选」：创建本人的 `pending` 新题，记录 `derived_from_id`，新题须重新复核。原作者可「下架 / 恢复」题目：下架题不参与组卷、不出现在默认列表，已有试卷快照不受影响。`approved` 题目 MUST NOT 被删除；`pending` 与 `rejected` 题目可由作者删除。

#### Scenario: 同科同事浏览题库

- **WHEN** 另一位数学教师打开数学题库
- **THEN** 能看到已通过题目的答案、解析与出处，看不到任何教师的待复核或已驳回题目

#### Scenario: 修改入库题目

- **WHEN** 教师对入库题目调用修改接口
- **THEN** 返回 409，提示复制为新候选；复制后新题为本人待复核，原题不变

#### Scenario: 下架后组卷

- **WHEN** 作者下架一道题后，有教师按配比组卷
- **THEN** 该题不会被选入新试卷，已包含它的旧试卷内容不变

### Requirement: 按配比组卷

`POST /api/teacher/quiz/papers` MUST 接受以下蓝图字段：

- 标题：1–160 字。
- 时长：10–180 分钟。
- 知识点范围：1–5 个词表内知识点。
- 题型分组：1–5 组，每组含题型、题数 1–20、每题分值 0.5–100（以 0.5 为步长）。
- 易 / 中 / 难百分比：均为非负整数，合计为 100。

全卷题数 MUST 不超过 50。

组卷 MUST 使用以下确定性算法，相同的题库状态与蓝图 MUST 得到相同结果：

1. 对每个题型分组，按最大余数法把题数分配到易 / 中 / 难：先取整数部分；剩余名额按小数部分从大到小分配，小数部分相同时按易、中、难的顺序分配。
2. 对每个「题型 × 难度」，从本学科题库中筛选候选：状态为 `approved`、未下架、题型和难度相符、知识点与范围有交集、本卷尚未选入。
3. 候选按以下顺序排序，取前 N 道：先按已出现在本人及他人定稿试卷中的次数升序，再按题号升序。

任一「题型 × 难度」候选不足时，MUST 返回 422 并列出全部缺口（题型、难度、需要数、可用数），不创建试卷，也不调用模型补题。

成功时创建 `draft` 试卷，为每道题保存创建时的内容快照与分值。草稿可以：

- 整体替换题目列表与分值（`PUT /papers/{id}`）。替换后的每道题 MUST 为本学科 `approved` 且未下架，同一题不得重复，题数不超过 50，分值规则同上。
- 调整顺序。

此类操作 MUST 携带 `revision`。

#### Scenario: 按 3:5:2 组卷

- **WHEN** 教师要求单选 10 题每题 5 分、解答 3 题每题 10 分，难度百分比为 30 / 50 / 20，题库充足
- **THEN** 单选按 3 / 5 / 2 抽题；解答的 0.9 / 1.5 / 0.6 先取整为 0 / 1 / 0，剩余 2 个名额按小数部分分给易与难，结果为 1 / 1 / 1。试卷共 13 题，总分 80

#### Scenario: 题库不足

- **WHEN** 题库中「多选 · 难」只有 1 道可用，而蓝图需要 2 道
- **THEN** 返回 422，列出「多选 · 难 需 2 可用 1」等全部缺口，不创建试卷

#### Scenario: 手工替换为下架题

- **WHEN** 教师在草稿中把一道题替换成已下架的题目
- **THEN** 返回 400，草稿保持原样

### Requirement: 试卷定稿与分班发布

作者 MUST 显式定稿草稿试卷（`POST /papers/{id}/finalize`，带 `revision`）。定稿后试卷只读；如需修改，用「复制为新草稿」生成新试卷。

发布（`POST /papers/{id}/publish`）MUST 满足以下条件：

- 试卷为 `final`；
- 请求带 `reviewed=true`，表示教师已核对学生卷不含答案；
- 目标为 1–30 个班级，全部在当前数据库的任教班级内。任一越权则整批返回 403，不创建任何资料。

学生卷 MUST 由服务端从题目快照渲染，不接受客户端提交的正文。学生卷包含：

- 标题、时长、总分；
- 按题型分节，标明每题分值；
- 连续编号的题干与选项；
- 填空空位，以及解答题的作答横线。

学生卷 MUST NOT 含答案、解析、出处、S 编号、题目内部编号。渲染结果 MUST 通过学生版去答案与链接校验。

每个目标班级 MUST 获得独立的 Material，具体要求：

- 文件为 `试卷标题（试卷）.md`。
- 标签依次为学科名、最多 3 个知识点、「试卷」「学生版」。
- 只复制正文实际使用的原图，复制前核对原图指纹；不一致时返回 409。
- MUST NOT 加入学生助手检索索引。
- 写入 `quiz_publications` 记录。

同一试卷、同一班级、同一学生卷指纹的重复发布 MUST 复用已有资料。

作者 MUST 可下载答案卷（`GET /papers/{id}/answer-key`），内容为每题答案、解析与出处摘录。答案卷 MUST NOT 进入任何班级资料。

#### Scenario: 发布到两个任教班级

- **WHEN** 教师核对定稿试卷后发布到本人任教的 101、102 班
- **THEN** 两班资料列表各出现一份不含答案的试卷，两班的学生助手检索都不会命中试卷内容

#### Scenario: 批次混入非任教班级

- **WHEN** 发布目标包含 201 班，而教师不任教该班
- **THEN** 返回 403，101、102 班也不创建资料

#### Scenario: 草稿试卷发布

- **WHEN** 教师对尚未定稿的试卷调用发布
- **THEN** 返回 409，提示先定稿

#### Scenario: 重复发布

- **WHEN** 教师对同一定稿试卷、同一班级再次发布
- **THEN** 返回原有资料编号，不新增资料

### Requirement: 命题范围隔离

所有 `/api/teacher/quiz/*` 接口 MUST 在服务端基于当前数据库身份校验：

- 学生访问返回 403。

- 候选题、生成记录与试卷仅作者可见。

教师学科或任教班级在数据库中变更后，后续请求 MUST 按新身份判定。前端隐藏按钮不构成权限控制。

- **THEN** 返回 403

- 题目详情显示该题的事件历史。

### Requirement: 题目内容显示

前端 MUST 用共用的 Markdown + KaTeX 渲染器（`MarkdownAnswer`）显示题目内容，包括：题库与待复核列表中的题干；题目详情中的题干、选项、答案与解析；草稿与已定稿试卷中的题干；学生卷预览；学生端打开的已发布试卷资料。编辑模式的输入框 MUST 显示原文，不做渲染。

选择题的每个选项 MUST 与题干一样经过渲染，公式 MUST NOT 以 `$…$` 源码显示；选项标签与内容 MUST 显示在同一行（选项含块级公式时除外）。

题目详情的答案：填空题与解答题的答案 MUST 经过同一渲染器，公式 MUST NOT 以 `$…$` 源码显示；填空题多个空位的答案按顺序用「、」分隔。单选、多选题的选项字母与判断题的「正确 / 错误」MUST 保持纯文本显示。答案卷下载的 Markdown 不在本需求范围内。

填空空位：渲染前，正文中连续 4 个及以上的下划线（与后端空位判定一致）MUST 转为按字面显示、不参与 Markdown 强调解析的形式，长度与数量不变。以下内容 MUST NOT 改动：代码块与行内代码、`$…$` / `$$…$$` 公式内部、尖括号自动链接、前面已有反斜杠的下划线、整行只有下划线的行（学生卷解答题作答横线与分隔线保持横线显示）。该规则作用于共用渲染器，因此在 AI 回答、讲义与学生稿预览中同样生效。

本需求只约束显示：MUST NOT 修改已保存的题目、试卷快照或学生卷 Markdown，不改变接口与服务端校验。

#### Scenario: 多空位填空题显示

- **WHEN** 教师在待复核列表或详情中查看题干为 `…则 $\overrightarrow{EF}$ 的坐标为____，____，____。` 的填空题
- **THEN** 页面显示 3 个空位，无加粗或斜体，公式正常渲染

#### Scenario: 空位与公式下标共存

- **WHEN** 题干同时含 `$ABCD-A_1B_1C_1D_1$` 与空位 `____`
- **THEN** 公式下标正常渲染，空位按字面显示，`.katex-error` 数为 0

#### Scenario: 选项含公式

- **WHEN** 教师打开选项为 `$(1,2,2)$`、`$(1,-2,2)$` 等的单选题详情（待复核或题库）
- **THEN** 四个选项都以数学符号渲染，每项「A. 内容」在同一行，页面 `.katex-error` 数为 0

#### Scenario: 填空与解答题答案含公式

- **WHEN** 教师打开答案为 `["$\frac{\sqrt{15}}{5}$"]` 的填空题详情，或答案为 `$\frac{\sqrt{3}}{3}$` 的解答题详情
- **THEN** 答案以数学符号渲染，不显示 `$` 源码，页面 `.katex-error` 数为 0

#### Scenario: 多空答案与选择判断答案

- **WHEN** 教师打开答案为 `["1","1","-1"]` 的填空题，以及单选、多选、判断题的详情
- **THEN** 填空答案显示为 `1、1、-1`；选择题显示选项字母（多选用「、」分隔），判断题显示「正确」或「错误」，与修改前一致

#### Scenario: 编辑答案时显示原文

- **WHEN** 教师在待复核详情中点击修改
- **THEN** 答案输入框显示原文（含 `$…$`），不做渲染

#### Scenario: 解答题作答横线不变

- **WHEN** 教师预览含解答题的学生卷
- **THEN** 作答区仍显示为横线，不变成一串下划线文字

#### Scenario: 学生端打开已发布试卷

- **WHEN** 学生在本班资料中预览含多空位填空题的已发布试卷
- **THEN** 每道填空题的空位数与题干原文一致

#### Scenario: 代码中的下划线

- **WHEN** 渲染内容在行内代码或代码块中含 `____`
- **THEN** 代码原样显示，不出现多余的反斜杠

### Requirement: 公式结构校验

公式结构检查是《结构化输出与逐题校验》中逐题校验的一部分。生成、修改保存和通过三处 MUST 执行同一检查。

检查范围：题干、每个选项文本、答案中的字符串（填空题的每一项、解答题的答案）、解析。判断题的布尔答案和选择题的选项字母不在范围内。规则如下：

- 转义的 `\$` 不计为公式定界符。其余 `$` MUST 按 `$$…$$`、`$…$` 成对，否则该字段判为「公式定界符 $ 不成对」。
- 每段公式内，反斜杠与其后一个字符视为一个整体，不参与计数（如 `\{`、`\}`、`\\`）。其余 `{` 与 `}` MUST 配对：从左到右任何时刻右括号都不多于左括号，且结束时数量相等，否则该字段判为「公式花括号不配对」。
- 公式外的花括号不检查。

任一字段不满足时：

- 该题判为未通过，原因 MUST 带字段名，如「选项 D 公式花括号不配对」「题干公式定界符 $ 不成对」；
- 生成时该题 MUST NOT 落库，修改保存与通过 MUST 返回 400。
- 服务端 MUST NOT 自动补全或删除括号与定界符。

本检查只针对 `$` 与花括号，MUST NOT 宣称证明公式可被正确渲染。已通过入库的题目不重新校验。

提示词 MUST 要求公式中的花括号成对，并要求把资料中 `\vec a`、`\frac12` 这类省略括号的写法改写为完整写法（`\vec{a}`、`\frac{1}{2}`）。

#### Scenario: 选项缺右括号

- **WHEN** 模型返回的单选题选项 D 为 `$\frac{1}{2}\vec{a}+\frac{1}{2}\vec{b}+\frac{2}{3}\vec{c$`，其余字段合法
- **THEN** 该题未通过校验，原因含「选项 D 公式花括号不配对」，不以待复核状态保存，其余合格题目照常保存

#### Scenario: 转义括号与环境不被误判

- **WHEN** 某题题干含 `$\{x\mid x>0\}$`，解析含 `$$\begin{cases}x+y=1\\x-y=0\end{cases}$$`
- **THEN** 公式结构检查通过

#### Scenario: 定界符不成对

- **WHEN** 某题解析为 `所以 $\frac{1}{2}`（缺少闭合的 `$`）
- **THEN** 该题未通过校验，原因含「解析公式定界符 $ 不成对」

#### Scenario: 转义的美元符号

- **WHEN** 某题题干为 `单价 \$5，求 $x$ 的值`
- **THEN** 公式结构检查通过

#### Scenario: 修改时引入不配对括号

- **WHEN** 作者修改一道待复核单选题，把选项 A 改为 `$\vec{a$` 后保存
- **THEN** 返回 400，原因含「选项 A 公式花括号不配对」，题目内容与 `revision` 不变

#### Scenario: 修改补齐括号后通过

- **WHEN** 作者把一道选项缺右括号的待复核题（变更前已入库）补齐括号后保存，再勾选确认并通过
- **THEN** 保存成功，通过后进入题库，复核记录标明「已修改」

### Requirement: 学生卷选项排版

服务端渲染学生卷时，每道题以 `n. 题干` 开头，记题号前缀 `n. ` 的长度为该题的缩进宽度。题干与选项的续行 MUST 按该宽度缩进，使其留在同一列表项内；题号到两位数时同样适用。

选择题（单选、多选）的选项 MUST 与题干分段，并按 A–D 顺序各占一行显示：

- 选项文本都不含换行时，选项之间用 Markdown 硬换行连接；
- 任一选项文本含换行时，每个选项单独成段。

判断题、填空题的输出不变；解答题的作答横线不变。本需求只改学生卷正文的排版，不改题目快照，也不改答案卷。已发布的班级资料 MUST NOT 被改写。排版改变后，含选择题的试卷重新发布时按新的学生卷指纹处理。

#### Scenario: 选项各占一行

- **WHEN** 教师预览一份含 2 道单选题的已定稿试卷
- **THEN** 每道单选题的题干单独一段，A、B、C、D 四个选项各占一行、与题干不在同一行，选项中的公式正常渲染，页面 `.katex-error` 为 0

#### Scenario: 第 10 题以后

- **WHEN** 试卷有 12 道单选题
- **THEN** 第 10–12 题的选项仍显示在各自题目下，题号 1–12 连续，选项不会脱离所在题目

#### Scenario: 选项含块级公式

- **WHEN** 某单选题的选项 B 含两行的 `$$…$$` 公式
- **THEN** 四个选项各自成段，块级公式正常渲染，后续题号连续

#### Scenario: 学生端打开新发布的试卷

- **WHEN** 教师在变更后发布一份含选择题的试卷，学生在本班资料中打开
- **THEN** 选择题选项各占一行，且学生卷不含答案、解析与出处

#### Scenario: 已发布资料不被改写

- **WHEN** 变更前已发布的试卷资料被学生再次打开
- **THEN** 资料内容与发布时一致
